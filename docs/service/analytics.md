# Аналитика сервиса

Раздел в `service-shell`, PR 328; целевое превью — `cantor-service-preview`. Источник расчётов: `src/features/service/analytics-model.ts`. Интерфейс не вызывает рабочие API Авито и CRM.

## Источники и период

Дневная статистика объявлений и разбивка по городам — отдельный иллюстративный набор за 1–16 ноября 2026 года. Он согласован с существующими карточками объявлений: 1660 показов, 318 просмотров, 29 контактов, 6420 ₽ расходов. Дневные и городские распределения не получены из Авито. Ставки и позиции не используются как источник просмотров или расходов.

Обращения, проведённые встречи, оплаты и возвраты вычисляются из текущего локального CRM-состояния браузера. Новые действия обновляют отчёты. Периоды включают обе даты, события относятся к календарному дню по Москве. Сравнение рекламы допустимо только при полном покрытии обоих периодов; отсутствие данных не означает нулевой результат.

## Формулы

- CTR = просмотры / показы × 100%; конверсия в контакт = контакты / просмотры × 100%.
- Цена просмотра = расходы / просмотры; цена контакта = расходы / контакты. При нулевом знаменателе значение отсутствует. Групповые проценты рассчитаны из сумм, а не усреднением процентов строк.
- Поступления — сумма оплат по датам получения. Возвраты учитываются по собственным датам. Поступления после возвратов = оплаты − возвраты.
- Новый ученик определяется первой оплатой с положительным остатком на конец выбранного периода. Повторная оплата не создаёт нового ученика. Будущие возвраты не переписывают более ранний отчёт.
- Проведённые диагностики считаются по отдельным завершённым встречам, независимо от оплат.
- Разница поступлений после возвратов и рекламных расходов — денежный результат до других затрат. Это не прибыль и не оценка окупаемости когорты. Расходы периода / новые ученики периода — отношение событий периода, а не доказанная стоимость привлечения когорты.

Город означает размещение объявления. В CRM отсутствует источник города: при таком фильтре показатели CRM не рассчитываются. Платежи привязываются к объявлению только при единственном известном источнике ученика; неоднозначные источники остаются отдельной строкой. Статусы обращений — текущий срез выбранных обращений, а не реконструкция истории этапов. В сообщениях отсутствуют временные метки, поэтому графиков скорости ответа нет.

## Проверки

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build:preview`. Предметные тесты модели проверяют сверку итогов, сочетания фильтров, взвешенные показатели, границы МСК, покрытие периодов, повторные оплаты, возвраты и неизвестную атрибуцию. `scripts/ops/analytics-browser-check.mjs` проверяет интерфейс и выгрузки в настоящем Chromium на 390 и 1440 px.
