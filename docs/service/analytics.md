# Аналитика сервиса

Раздел в `service-shell`, PR 328; целевое превью — `cantor-service-preview`. Источник расчётов: `src/features/service/analytics-model.ts`. Интерфейс не вызывает рабочие API Авито и CRM.

## Источники и период

Дневная статистика объявлений и разбивка по городам — отдельный иллюстративный набор за 1–16 ноября 2026 года. Он согласован с существующими карточками объявлений: 1660 показов, 318 просмотров, 29 контактов, 6420 ₽ расходов. Дневные и городские распределения не получены из Авито. Ставки и позиции не используются как источник просмотров или расходов.

Обращения, проведённые встречи, оплаты и возвраты вычисляются из текущего локального CRM-состояния браузера. Новые действия обновляют отчёты. Периоды включают обе даты, события относятся к календарному дню по Москве. Сравнение рекламы допустимо только при полном покрытии обоих периодов; отсутствие данных не означает нулевой результат.

## Формулы

- CTR = просмотры / показы × 100%; конверсия в контакт = контакты / просмотры × 100%.
- Цена просмотра = расходы / просмотры; цена контакта = расходы / контакты. При нулевом знаменателе значение отсутствует. Групповые проценты рассчитаны из сумм, а не усреднением процентов строк.
- Поступления — сумма оплат по датам получения. Возвраты учитываются по собственным датам. Поступления после возвратов = оплаты − возвраты.
- Новый ученик определяется первой оплатой с положительным остатком на конец выбранного периода. Повторная оплата не создаёт нового ученика. Будущие возвраты не переписывают более ранний отчёт.
- Проведённые диагностики считаются по отдельным завершённым встречам, независимо от оплат.
- Разница поступлений после возвратов и рекламных расходов — денежный результат до других затрат. Это не прибыль и не оценка окупаемости когорты. Расходы периода / новые ученики периода — отношение событий периода, а не доказанная стоимость привлечения когорты.

Город означает размещение объявления. Городская атрибуция CRM заполнена не для всех записей и пока не используется для оплаты: при фильтре города показатели CRM не рассчитываются. Платежи привязываются к объявлению только при единственном известном источнике ученика; неоднозначные источники остаются отдельной строкой. Статусы обращений — текущий срез выбранных обращений, а не реконструкция истории этапов. Рекомендации по ответам учитывают последнее фактическое сообщение и остановку таймера; причины отказов берутся только из закрытых обращений с сохранённой причиной.

## Проверки

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build:preview`. Предметные тесты модели проверяют сверку итогов, сочетания фильтров, взвешенные показатели, границы МСК, покрытие периодов, повторные оплаты, возвраты и неизвестную атрибуцию. `scripts/ops/analytics-browser-check.mjs` проверяет интерфейс и выгрузки в настоящем Chromium на 390 и 1440 px.


## Компоновка и экономика LTV

Четыре отчёта: обзор, объявления (включая города), диалоги, экономика. Все фильтры, пресеты и CSV находятся в единой панели. Даты раскрываются по иконке; общие компоненты service-controls.tsx реализуют собственные календари и меню. Пресет «Вчера» берёт предыдущий календарный день Москвы. В режиме «Все» график показывает исходные количества: показы по левой шкале, просмотры и контакты по правой; легенда обозначает шкалы. Нормализации или вымышленных величин нет.

Воронка: расход / показы, расход / просмотры, расход / контакты; для просмотров и контактов дополнительно показаны конверсии. Городская матрица объявления сводится к агрегатам по объявлениям и городам при любом сочетании фильтров. Таблица по дням включает CTR, конверсию в контакт и цены этапов.

Правило базы знаний (курс «Воронка, конверсии и экономика»): стоимость привлечения ученика должна составлять до 20% от LTV. LTV вводится преподавателем как ожидаемая сумма за всё обучение (цена занятия × занятий в месяц × месяцев обучения) и сохраняется в браузере отдельно для workspace. Оценка расхода на ученика = рекламные расходы периода / новые платящие ученики периода. Отношение этой оценки к LTV сравнивается с 20%; равенство считается допустимым. Это оценка событий периода, не доказанный когортный CAC. Без LTV, новых учеников или полного покрытия данных заключение не выводится. Проверка границы использует целые копейки.

Оплаты и возвраты доступны прямо в экономике. Можно исправить сумму/дату оплаты и зарегистрировать частичный или полный фактически выполненный возврат. Исправление сохраняет ID и ученика, не может уменьшать оплату ниже суммы возвратов или переносить оплату за дату возврата. Возврат не превышает остаток, имеет собственную дату и не имитирует банковскую транзакцию. На телефоне действия и суммы видны в карточках платежей. Действия отражаются в CRM и аналитике без повторной регистрации ученика.
