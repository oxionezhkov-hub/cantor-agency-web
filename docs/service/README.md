# Cantor: переход от агентства к сервису

Рабочая редакция от 16 ноября 2026 года. Подготовлена по полному документу владельца продукта и коду PR 328.

1. [Разбор продукта и текущей реализации](product-review.md) — что строим, почему текущая оболочка не решает задачу, расхождения и решения.
2. [ТЗ первой рабочей версии](specification.md) — согласованные решения, сценарии, данные, интеграции, приёмка и порядок реализации.
3. [Правила диалогов и напоминаний](dialog-policy.md) — методика из базы знаний с учётом прямых указаний владельца.

Текущее [облачное превью](https://cantor-service-preview.oxion-ezhkov.workers.dev) обновляется отдельно от main; пока использует демонстрационные данные.

[Точечные требования владельца к диалогам и CRM](dialog-workbench.md).

Разработка: [план проходов и референсы](implementation-plan.md), [журнал результатов и проверки](WORKLOG.md), [серверный контракт CRM и ограничения](server-crm.md).

Статусы требований: **источник** — явно описано в полном ТЗ; **предложение** — новая детализация для разработки; **согласовано владельцем** — ответ, полученный в текущем чате и внесённый в ТЗ; **решение владельца требуется** — открытое бизнес-условие. Открытые вопросы задаются в чате, а не оставляются только в документе. Основные продуктовые вопросы закрыты ответами владельца (см. начало ТЗ). Участники пилота выбираются позже и не блокируют разработку. Это ТЗ для обсуждения и реализации, а не отчёт о готовом сервисе. Рабочие API и внешние кабинеты при подготовке не изменялись; доступность возможностей Авито на конкретном приложении не проверялась.
