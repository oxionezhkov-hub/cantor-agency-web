# Живое чтение Авито в защищённом превью Добрыниной

20.11.2026. Только PR 328 / `cantor-service-preview`; production mainweb и данные Авито не изменяются.

## Что подключено

Защищённый `GET /api/demo/live` обслуживает фиксированное workspace/account. Авторизация — действующая подписанная HttpOnly-сессия превью или текущий пароль входа; это доступ именно к единственному защищённому пространству, а не произвольный выбор аккаунта. Отдельный admin-допуск прежнего audit export остаётся независимым. Секрет администратора, credentials Авито и internal gate в браузер не передаются.

Новая интеграция использует отдельный **непубличный** Worker `cantor-avito-live-direct`, credentials отправляются только `https://api.avito.ru/token`, bearer только официальному API Авито. Старый административный адаптер не менялся. Обновление старого адаптера через существующий российский прокси auto-review отклонил; вместо обхода создан официальный прямой транспорт, который успешно проверен. Дополнительное согласие на Yandex для новой live-интеграции не требуется: она его не использует.

Чтения:

- `ads`: `/core/v1/items`, фиксированные статусы active/old/removed/blocked/rejected; до 6 страниц по 50. Уникальные IDs, обнаружение повторившейся страницы, honest truncated. Текущие название/цена/статус обновляются; тексты, фотографии и ставки, которых нет в ответе списка, остаются историческими и не объявляются свежими.
- `autoload`: текущая загрузка v4 + до 4 страниц по 50 её объявлений. Используются фактические поля avito_id, ad_id, avito_status, messages(type=error). Ошибки соединяются с карточкой только по точному AvitoId или постоянному Id фида. Они показаны в существующем столбце «Статус» ссылкой на автозагрузку; несопоставленные ошибки остаются в отчёте фида.
- `chats`: последние 100 записей сначала; явная загрузка более ранних по 50 до offset950, список отмечен частичным. Имена/последние события — только в защищённом UI. Исторические карточки сохраняются для доступности старых CRM-записей.
- `messages`: ленивый GET v3 для выбранного чата, сначала 50; более ранние страницы — по кнопке, максимум offset950. ID должен принадлежать серверному списку уже прочитанных чатов либо историческому снимку этого пространства. Реальный формат ID с `~` разрешён; слэши/подмена аккаунта запрещены. Чтение **не** помечает чат прочитанным в Авито. При недоступности остаётся последняя хорошая страница либо явно обозначенная историческая история.
- `metrics`: кошелёк, CPA v3 баланс, дневная статистика объявлений за 14 завершённых дней по Москве, отдельная детализация расходов профиля. Никаких придуманных доплат 100 ₽/сутки или переноса средств в расходы.

Bootstrap больше не выдаёт сразу все тела исторических сообщений; только метаданные и последнее событие. Реальная отправка в защищённом пространстве отключена (`disconnectedAdapter`), никакой локальный «успех» не выдаётся за доставку. Mark-read, отправка/редактирование, запуск загрузки, изменение бюджета/ставки, webhook registration не вызываются.

## Обновление и последнее хорошее состояние

Клиент последовательно проверяет разделы при входе и раз в 60 секунд, только в видимой вкладке. Открытая переписка проверяется раз в 30 секунд. Серверный кэш: chats/messages 20 секунд, ads/autoload 120 секунд, metrics 300 секунд. Это near-real-time, не гарантия мгновенного события. Даты и частичность раскрываются только через кнопку «Актуальность данных Авито» в «Настройки → Кабинет → Кабинет Авито» (доступное модальное окно); денежные остатки имеют собственные отметки времени. Локальные редакторы не перемонтируются при обновлении; новые данные не сохраняются в localStorage.

Последние хорошие проекции/страницы хранятся только в отдельном KV превью DEMO_DATA с retention 24 часа. Исторический snapshot.gz не перезаписывается. В production AVITO_KV адаптер читает только один account-key, никаких put/list. Нормальные пользовательские изменения CRM остаются локальным прототипом, не становятся постоянной рабочей CRM.

Budget: preview LIVE_READ_LIMIT30/min на пространство; direct SOURCE_LIMIT60/min; каждая страница 50, ответы source ≤256KiB, проекция раздела ≤300KiB; явная пагинация и дедлайны, без бесконечных циклов. Неполный/ошибочный ответ не заменяется нулями. Ошибка содержит origin preview_limiter/source_limiter/avito/network/mapping; источник 429 больше не угадывается по одному статусу. API CPA balance и spendings имеют собственный лимит 1/min; кэш metrics300s и отсутствие быстрых автоматических повторов не создают шквал запросов.

## Деньги, единицы и прогноз

Кошелёк: `/core/v1/accounts/{user}/balance/`, real/bonus в рублях; показаны отдельно. CPA: `POST /cpa/v3/balanceInfo {}`, поле balance — целое количество копеек, делится на100. Ноль не является отсутствием данных; отрицательный остаток не прячется. Кошелёк, бонусы и CPA никогда не складываются в общий доступный бюджет.

`stats/v2/items` allSpending приходит в копейках. Для `stats/v2/spendings` обязателен spendingTypes; в новом запросе ['all']. Схема ответа определяет groupings[].spendings[].value в **рублях**, несмотря на противоречивые общие описания. Это дополнительно сверено на живом периоде: сумма presence совпала с allSpending/100; дополнительное деление profile-value на100 совпадения не даёт. Расходы профиля включают rest/прочие услуги, они не подменяются одними расходами объявлений. Источник схемы: публичная копия официального каталога от03.10.2026 (`MissiaL/avito-api`, references/avito-api-openapi.json), фактическая форма успешно проверена20.11.

Прогноз сейчас честно **недоступен**: API подтвердил расходы и остатки, но не привязку всего состава расхода к конкретному пополняемому балансу. Модель допускает расчёт только при подтверждённом eligibleBalance, свежем остатке, полном репрезентативном периоде ≥7 завершённых дней и положительном среднем. Формула: подтверждённый доступный баланс / средний дневной расход этого баланса; дата — момент оценки плюс это число дней. Бонусы без подтверждения применимости не используются. Тесты проверяют отдельные остатки, ноль/отсутствие/устаревание, неполную историю и запрет выдуманного прогноза.

## Конфигурация и проверка

`wrangler.live-direct.jsonc` — непубличный direct Worker; `wrangler.preview.jsonc` — binding LIVE_READ_SOURCE, gate secret LIVE_READ_GATE, flag LIVE_READ_ENABLED=direct-v1, limiter. Source secret AUDIT_GATE_SHA256 независим от админ-пароля. При отсутствии любого допуска/лимитера/привязки — deny до чтения credential record. Новые secrets созданы в Cloudflare, в git значений нет.

Живые проверки (только boolean/metadata output): прямые ads и current-autoload complete; chats partial; GET небольшой страницы messages hasText/hasTimestamp=true, без fallback; кошелёк/аванс — числовые отдельно; 14дней stats и expenseBreakdown получены без ошибок; сопоставленная ошибка автозагрузки присутствует. Raw сообщения, имена, IDs и значения ключей не выводились. Это проверка доступности чтений, не разрешение на любые операции API.

Финальная UI-проверка опубликованного превью: отдельные живые остатки и история расходов отрисовались, ленивый GET вернул текст, переписка обновилась без pageerror. Синтетический браузер390/1440 проверил те же сценарии, точное размещение ошибки в ячейке существующего статуса и отсутствие изменяющих API-вызовов. Анонимный live401, POST405, подмена аккаунта400, обычный audit403. Секрет администратора и пароль входа отсутствуют в public assets (проверено boolean-only). Реальный пример дашборда сохранён только локально `/tmp/cantor-live-deployed/dashboard-funds.png`; финансовые значения не коммитятся в публичный репозиторий.

Исторический429 из прежнего audit-файла нельзя задним числом однозначно приписать Avito или внутреннему лимитеру: origin там не сохранялся. Новый исправленный spendings-запрос успешно выполнен напрямую; будущие ошибки различаются по origin. Вызывать заведомо лишние запросы ради искусственного429 не требуется.

## Исправление списка объявлений, 20.11.2026

Причины: новые записи живого списка ранее получали пустые фотографии/NaN вместо проекции по ID; обновление сохраняло устаревшие метрики из локального состояния и могло терять пробные правки. Длинная ошибка автозагрузки наследовала nowrap таблицы и выталкивала статистику за экран. По умолчанию алфавитный список начинался с архивных карточек, у части которых отсутствуют фото в историческом источнике.

Исправлено: единое преобразование данных карточки, восстановление защищённых ссылок фото по точному ID, сохранение известной цены при неполном live-ответе, обновление известных показателей и раздельное сохранение локальных правок. Неизвестные значения новой карточки не заимствуются из первой строки. По прямому уточнению владельца начальная сортировка «Статус ↓» показывает опубликованные объявления первыми; ручная сортировка доступна. Ошибки автозагрузки переносятся в ограниченной ячейке статуса.

При проверке bootstrap отдавал 216 исторических объявлений, 153 с фото; все 153 изображения загрузились. Отсутствие исходного фото у остальных карточек не заменяется вымышленной картинкой. Показатели объявлений остаются за подтверждённый defaultPeriod исторического среза; свежий общий расход/баланс не превращается в статистику каждой карточки. Сбой live-источника сохраняет последние хорошие данные. Для различения причины ошибок добавлен ограниченный sourceCode без тела ответа/секретов.
