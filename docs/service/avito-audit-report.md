# Ограниченный отчёт Авито для Добрыниной

Кнопка: Настройки → Кабинет → «Собрать отчёт Авито». Реальные вызовы при разработке не выполнялись. Доступны фиксированные чтения профиля, объявлений, метаданных чатов, статистики/расходов за вчера по Москве, кошелька, автозагрузки v4, рейтинга и метаданных отзывов. JSON содержит статусы, ошибки, страницы, продолжение, время и покрытие. Тела сообщений вообще не запрашиваются. Профиль проверяется по numeric userId, личные поля отбрасываются. Все проекции числовые; сырые ответы не сохраняются.

## Настройка и состояние развёртывания

Общий пароль превью не является разрешением на живой экспорт. По отдельному запросу владельца 20.11.2026 адаптер и доступы настроены на `cantor-service-preview`; production `mainweb` не изменялся. Проверены identity и balance (available, одна попытка), anonymous 401 и ordinary 403. Секреты не входят в репозиторий. При потере любого необходимого binding/секрета сервер снова отказывает.

Для включения оператору развёртывания необходимо:

1. Отдельный secret `AVITO_AUDIT_ADMIN_SHA256` — SHA-256 отдельного сильного допуска администратора; общий пароль панели не переиспользовать. Оператор должен также иметь действующий вход в превью. Поле в UI передаётся по HTTPS и хранится только в памяти компонента, не в URL/хранилище браузера. Это временный административный допуск, а не промышленная модель RBAC.
2. `AVITO_AUDIT_ENABLED=dobrynina-read-v1` и `AVITO_AUDIT_USER_ID=388298238` — проверенный numeric Avito userId уже подключённого кабинета `6c974a5d5326`, workspace `elena-dobrynina`. Не получать его из пользовательского параметра, не угадывать по имени.
3. Изолированный Cloudflare service binding `AVITO_AUDIT_SOURCE`. Реализован в `service-shell/scripts/ops/avito-audit-source.mjs`, Worker `cantor-avito-audit-source`, привязан к превью. Нельзя подставлять общий административный Worker или публичный raw-proxy. Требуется отдельный адаптер только чтения, закреплённый за этим подключением, с серверными credentials. Передавать ему разрешённые запросы `https://api.avito.ru` из `avito-audit.mjs`; он проверяет origin/path/method, закреплённые workspace/account/userId, сам добавляет авторизацию и не выполняет sync/pull/записи/обновления клиентских данных. В ответе обязательны проверенные `x-cantor-account: 6c974a5d5326` и `x-cantor-workspace: elena-dobrynina`. Эти заголовки — контракт доверенного binding, не подтверждение от публичного Avito. При несоответствии экспорт прекращается. Новый token при необходимости оформляется через уже существующий изолированный вызов `/avito-call` российского прокси; credentials берутся только из одного существующего KV ключа `account:6c974a5d5326`. Значения не возвращаются. KV put/list отсутствуют.
4. Rate-limit binding `AVITO_AUDIT_LIMIT`, рекомендуемое окно 60 секунд / 12 запросов на фиксированный workspace. Без него live чтения запрещены. Пример конфигурации нужно включать только вместе с проверенным binding: `{ "name": "AVITO_AUDIT_LIMIT", "namespace_id": "<новый выделенный ID>", "simple": { "limit": 12, "period": 60 } }`.
5. Сверить текущую официальную OpenAPI и подтвердить схемы/права на тестовом кабинете. В частности spendings может вернуть ошибку схемы — это отражается как ошибка, не нулевой расход. Выполнить проверку доступа администратору и отказов другому пользователю до включения.

## Бюджеты и продолжение

Только GET к маршруту отчёта; section из фиксированного списка, page 0–19, посторонние/повторные параметры отвергаются. Только статистика и расходы используют downstream POST к подтверждённым read-only методам. Нет сообщений, запуска автозагрузки, изменения ставки, покупки услуг, отметки прочтения или произвольного пути. Binding обязан независимо обеспечить такой же deny-by-default.

Одна страница за раз, 50 элементов; максимум 20 страниц раздела. Пустая последняя страница тоже считается подтверждённым завершением. Если страница полная, отчёт сохраняет следующий номер; на границе отмечается truncated. Полный список может меняться во время пагинации: это не атомарный снимок и не доказательство отсутствия дублей между страницами.

Сервер: до трёх попыток на страницу при сетевой ошибке, 429 или 5xx; backoff/Retry-After ограничен 2 секундами. Fetch и чтение ответа ограничены дедлайнами по 5 секунд; размер ответа 256 КБ. Ответы 401/403/404 не повторяются. Клиент: дедлайн страницы 22 секунды, максимум 10 страниц/45 секунд за явный проход, 80 страниц всего в сессии, JSON состояния не более 500 КБ. У клиента может сработать дедлайн раньше сервера; результат тогда считается незавершённым, повторяется только read-only страница. Нет фонового неограниченного цикла. Клиентский бюджет — ограничение интерфейса, серверные rate-limit и page bounds работают независимо.

Успешные страницы сохраняются **только в памяти этой вкладки**. «Продолжить / повторить ошибки» пропускает успешные страницы, повторяет незавершённые; перезагрузка, закрытие/уход из компонента теряют прогресс. Частичный JSON скачивается в любое время после первой страницы и показывает ошибки/coverage/cursors. После лимита 80 требуется новая сессия; бесконечного продолжения нет. Секрет администратора не входит в файл.

Проверка доступности переписок — список чатов, не чтение тел. Статистика выгружается за один завершённый день; агрегаты и остатки не являются бухгалтерской сверкой. Ставки, продвижение, SBC, аудио/голосовые, фотографии и тарифы других вертикалей в отчёте явно исключены. Диагностики/оплаты учеников — данные Cantor, не Avito API.


## Внутренняя защита адаптера и фактическая проверка

Source дополнительно требует `AUDIT_GATE_SHA256`, проверяющий заголовок, который preview передаёт из своего secret `AVITO_AUDIT_GATE`. Это независимый случайный внутренний ключ, не пароль администратора. До проверки этого ключа и `SOURCE_LIMIT` адаптер не читает KV. В обоих Workers лимит 12 запросов/60 секунд на фиксированное пространство. Source workers.dev и preview URLs отключены. Разрешены только точные пути/query/body из allowlist; любое другое объявление аккаунта, метод или параметр отклоняется. Редиректы обрабатываются manual и не выполняются: режим error не поддерживается Request в текущем Workers runtime.

Первый upload был отклонён автоматической проверкой из-за отсутствия независимого gate/лимитера в адаптере. После добавления deny-before-KV и проверки синтетическими тестами безопасный вариант принят. Это не обход проверки: устранена отмеченная граница доступа.

Отдельный сильный пароль администратора сгенерирован локально в защищённый файл вне репозитория; в Cloudflare хранится только его SHA-256 secret. Для передачи владельцу нужен защищённый канал, значение в чате/отчётах не публикуется. Для повторной локальной проверки путь можно передать через `AVITO_AUDIT_ADMIN_FILE`. Файл не является артефактом для коммита.

20.11.2026: HTTP проверки подтвердили anonymous401 / ordinary403 / admin identity200 available и balance200 available без вывода значений баланса. Полная доступность всех девяти разделов не заявляется: тестировались только указанные чтения, не отправка сообщений и не публикация. Статистика, список чатов и отзывы не проверялись на живых данных в этом проходе.

Живой браузерный сценарий также подтверждён на фактическом URL превью: неправильный административный допуск отклонён; правильный выполнил identity-read; пауза сохранила первую страницу, частичный JSON скачан и проверен без секретов. Свежие public assets загружены отдельной upload-session и применены с сохранением всех существующих bindings/secrets. Для браузерного теста в среде с HTTPS-прокси включён `ignoreHTTPSErrors`; обычный HTTPS-клиент проверял API с системным доверием сертификатам. Полный отчёт всех разделов не запускался.
