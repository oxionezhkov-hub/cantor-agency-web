Состояние сборки — `/__preview.json`, страницы и ответ метаданных не кешируются. Root `wrangler.jsonc` и workflow main не менять ради превью.

CLI Wrangler в среде есть (`/workspace/.cloud-tools/node_modules/.bin/wrangler`, 4.162.0), но локальной авторизации нет. Для развёртывания доступен подключённый Cloudflare plugin; не просить пользователя вставлять токены в чат. Account ID: `db4d58ea02f7b78479cf98f3a55f0dd4`.

Последовательность публикации через подключённый Cloudflare API:

1. Собрать `build:preview`, получить JSON-манифест `node scripts/ops/preview-assets.mjs --manifest`.
2. Cloudflare connector: `POST /accounts/{account}/workers/scripts/cantor-service-preview/assets-upload-session` с `{manifest}`. JWT результата сохранить вне репозитория в `/workspace/.cloud-tools/config/cantor-assets-session.json` вместе с `accountId` и `buckets`, не печатая токен в отчёте.
3. `node scripts/ops/preview-assets.mjs` загружает подписанные файлы; completion JWT остаётся в `/workspace/.cloud-tools/config/cantor-assets-completion.json`. Оба приватных файла — права 0600.
4. Подключённый API `PUT /accounts/{account}/workers/scripts/cantor-service-preview`: multipart metadata с `main_module: preview.mjs`, compatibility_date 2026-11-16, binding ASSETS типа assets, `assets.jwt` из completion-файла, `assets.config` с SPA fallback и run_worker_first. Модуль — `scripts/ops/preview-worker.mjs`. Никаких production bindings и секретов.
5. Проверить домен, `/__preview.json`, отказ `/api/*`; прогнать browser-check на внешнем URL. Только после этого отправлять ссылку Олегу как проверенную.

### Исправление сборки публичного превью

Внешний прогон обнаружил React hydration error #418 в первоначальном варианте статического Start shell; локальный dev SSR этого не выявил. Исправлено: отдельный чисто клиентский вход `preview.html` + `src/preview.tsx` + `vite.preview.config.ts`, который использует те же компоненты приложения и маршруты разделов. Production `vite.config.ts` возвращён к исходному состоянию. Сборка превью не зависит от SSR/Nitro/Grok-окружения. Локальный прогон именно собранной статики на 390/1440 px прошёл без ошибок, а не только dev-сервер.

У Chromium в этой среде нет доверия к CA сетевого прокси. Для внешнего браузерного теста используется `CANTOR_BROWSER_VALIDATED_TRANSPORT=1 node scripts/ops/browser-check.mjs <URL> <tmp-directory>`: запросы страницы и её ресурсов доставляет Node с системным proxy и NODE_EXTRA_CA_CERTS; TLS проверяется. В Chromium не включаются ignoreHTTPSErrors и глобальное отключение сертификатов. Это адаптер тестового транспорта, не изменение сайта. Картинки и UI всё равно исполняются настоящим Chromium в контексте внешнего домена.

## Проход 16.11.2026: CRM и связанные показатели

Вместо независимых массивов и идентификации по имени введены валидируемые сущности рабочего пространства, заявки, ученика, встречи, оплаты и возврата со стабильными ID. Суммы хранятся целыми копейками. Команды проверяют принадлежность workspace, повторный requestId, пересечения/прошедшие окна, доступность исхода встречи и границы возвратов. Перенос сохраняет историю и ID; отмена освобождает окно.

Рабочий демонстрационный срез: из рекомендации можно открыть конкретное объявление, диалог, запись или ученика; записать заявку, отменить/перенести встречу, после её окончания отметить проведение/неявку, внести оплату с копейками. Повторные оплаты не создают нового ученика; диагностики не вычисляются из оплат. Обзор отделяет статистику Авито от CRM и поясняет ограничение атрибуции расходов. Оплата без диагностики допустима. Состояние синхронизируется между экранами/вкладками, переживает перезагрузку; старые локальные записи мигрируются без удаления исходных ключей. Ошибки чтения и заполненного хранилища отображаются, успешная запись при ошибке не имитируется.

Убраны оставшиеся вымышленные нормативы: час на блокировку, бюджет 100 ₽/день, универсальное напоминание за три часа. Для «нескольких часов» в демо явно используется техническое значение 3 часа; окончательная конфигурация нужна на сервере. Встречи имеют собственные исходы вместо бессрочного напоминания.

Проверки до публикации:
- typecheck, lint, build:preview и git diff --check;
- полный npm test: 199 успешно + 4 явно пропущенных проверки внешней документации Grok; отдельный typed этап — 88 успешно, без пропусков. Исходные восемь падений исправлены переносимыми временными fixtures, авторизация приложения не отключалась. Проверки команд/утилит не скрыты;
- новый браузерный CRM-сценарий на 390/1440 px: запись, конфликт занятых окон, отмена/повторная запись, перенос, оплата 1234,50 и повторная 55,50, сохранение после reload, обновление другой вкладки, неявка и проведение с управляемыми часами;
- шесть разделов на обеих ширинах: без pageErrors/переполнения, переключение и сохранение темы. Скриншоты /tmp/cantor-crm-visual-checks, обзор просмотрен визуально на обеих ширинах.

Ограничения: это по-прежнему явно маркированное демо/localStorage, без серверного хранения, авторизации клиентов, атомарной защиты от одновременной записи двух вкладок и реальных сообщений/списаний. Возвраты сейчас проверены на уровне модели, интерфейс администратора ещё не реализован. Реальные API не подключались. Следующий приоритет — серверный контракт, изоляция клиентов и конкурентная запись с переиспользованием существующего Worker; затем настройки режимов диалогов и подписки. Участников пилота не выбирали.
