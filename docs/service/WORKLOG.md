Для внешнего браузерного теста используется `CANTOR_BROWSER_VALIDATED_TRANSPORT=1 node scripts/ops/browser-check.mjs <URL> <tmp-directory>`: запросы страницы и её ресурсов доставляет Node с системным proxy и NODE_EXTRA_CA_CERTS; TLS проверяется. Картинки и UI всё равно исполняются настоящим Chromium в контексте внешнего домена.

## Проход 16.11.2026: CRM и связанные показатели

Вместо независимых массивов и идентификации по имени введены валидируемые сущности рабочего пространства, заявки, ученика, встречи, оплаты и возврата со стабильными ID. Суммы хранятся целыми копейками. Команды проверяют принадлежность workspace, повторный requestId, пересечения/прошедшие окна, доступность исхода встречи и границы возвратов. Перенос сохраняет историю и ID; отмена освобождает окно.

Рабочий демонстрационный срез: из рекомендации можно открыть конкретное объявление, диалог, запись или ученика; записать заявку, отменить/перенести встречу, после её окончания отметить проведение/неявку, внести оплату с копейками. Повторные оплаты не создают нового ученика; диагностики не вычисляются из оплат. Обзор отделяет статистику Авито от CRM и поясняет ограничение атрибуции расходов. Оплата без диагностики допустима. Состояние синхронизируется между экранами/вкладками, переживает перезагрузку; старые локальные записи мигрируются без удаления исходных ключей. Ошибки чтения и заполненного хранилища отображаются, успешная запись при ошибке не имитируется.

Убраны оставшиеся вымышленные нормативы: час на блокировку, бюджет 100 ₽/день, универсальное напоминание за три часа. Для «нескольких часов» в демо явно используется техническое значение 3 часа; окончательная конфигурация нужна на сервере. Встречи имеют собственные исходы вместо бессрочного напоминания.

### Реализация

- Добавлены SQL-репозиторий и маршрут `/api/service/crm` в существующий TanStack Start. Используются уже установленные PostgreSQL/PGLite, `getSql()` и проверка сессии Better Auth. - Аддитивная миграция `0002_service_crm.sql`: снимок пространства/версия, членство, атомарный журнал команд (автор, время, содержимое, requestId). В production она не запускалась. Публичного создания членства и автоматического импорта демоданных нет.
- Доступ по проверенной сессии и активному членству; общего dev-user fallback нет. В production временная PGLite-база запрещена для API. Владелец/назначенный куратор могут менять CRM, viewer читает. Чужое пространство не раскрывается; отзыв и понижение роли повторно проверяются перед записью.

- Один SQL statement с compare-and-set версии меняет состояние и журнал вместе; нет mutex в памяти. Конфликт возвращает 409 с доступным актуальным снимком. Повтор того же ключа/автора/команды не создаёт второй платёж; другой payload/автор даёт конфликт. Исправлена гонка чтения квитанции после старого снимка — повтор перечитывает свежий снимок.

### Что теперь можно пройти в интерфейсе

- В «Моих диалогах» — единый список семи обращений с поиском по имени/ученику/предмету и фильтрами по реальному этапу. Сверху списка люди, которым требуется следующий шаг. Выбор конкретного обращения сохраняется в URL; мобильная карточка имеет возврат к списку.
- Одна карточка связывает участника, ученика, исходное объявление, переписку, запись, оплаты и историю. Внутри показываются только записи/платежи выбранного человека; при проверке чужие данные не подмешиваются.
- Черновик сохраняется и восстанавливается после reload, отдельно по ID обращения. Кнопка копирования действительно копирует текст. Успех копирования не отмечает сообщение доставленным. Отправки в Авито нет; ИИ не генерировал эти ответы.
- Для приглашения преподаватель выбирает реально свободное будущее окно, текст собирается по методике диагностики и точной дате/времени МСК. Занятые окна исключаются, приглашение само не бронирует встречу. Старые заранее написанные ответы с занятым временем больше не подставляются.
- Из карточки можно записать, перенести/отменить, после окончания отметить проведение/неявку и внести оплату с копейками. Этап меняется от событий: запись → нужен исход → после диагностики → ученик. Повторная оплата увеличивает сумму, не число учеников. Суммы/проведённые встречи обновляются в обзоре и аналитике.
- Закрытие требует причину, отменяет активную запись и освобождает время. История/оплаты сохраняются; можно вернуть человека в работу. Закрытому обращению нельзя создать запись, пока оно не возвращено. Причина закрытия/перенос/отмена/возврат/оплаты видны в хронологии; ISO-технические строки переноса заменены читаемыми датами.
- В карточке существующей записи убрана лишняя форма «записать ещё раз»; повторный слот не предлагается. Пользовательские запреты сохранены: только светлый интерфейс, без хлебных крошек, верхних вводных заголовков, демоплашек и футера.
