# Массовое создание объявлений

Источник: прямой запрос владельца в чате 18.11.2026 — собственный путь без обязательной Google Таблицы, генерация и размножение по городам без ручного заполнения каждой карточки.

## Предлагаемый путь и текущая реализация

В подразделе «ИИ-генерация» по умолчанию открывается партия: предложение преподавателя → список городов → проверка → добавление черновиков. Старый редактор доступен через «Одно объявление». Можно взять за основу существующую карточку; общие фотографии и цена применяются ко всем вариантам. Вручную заполненный текст не требует ИИ.

Workers AI готовит 1–3 редактируемых варианта заголовка и текста, а не делает отдельный запрос для каждого города. Данные отправляются модели только по кнопке. Город подставляется по явному шаблону `{город}`; дедупликация названий городов не учитывает географические омонимы. До 100 названий × 3 варианта, проверка по 15 строк. Это предел интерфейса прототипа, не квота продукта или разрешение Авито на публикацию. Фото общие: исходные или HTTPS-ссылки; генерация новых изображений в партии не подключена.

Перед добавлением пользователь проверяет партию, может изменить заголовки и исключить отдельные строки; совпадения заголовка и города с существующими объявлениями подсвечиваются. Каждый черновик имеет независимый UUID, статус «Черновик» и появляется в общем списке. Разные формулировки сами по себе не делают допустимыми дубли объявлений: перед публикацией нужен отдельный контроль требований Авито, категории, адреса, фотографии, цены и доступности размещения по городам.

## Границы прототипа

Черновики и история живут в памяти страницы до обновления. Нет серверного хранения партий, импорта в Google Таблицу, сборки нового действующего XML, отправки или подтверждения публикации Авито. Исходный защищённый срез не изменяется. Отчёт текущей автозагрузки не является отчётом по созданной партии.

Текстовая модель: `@cf/meta/llama-3.1-8b-instruct-fast` через серверный binding AI. Маршрут `/api/campaign/suggest`: авторизация превью, проверка Origin, максимум 20 KB тела / 6000 символов исходных данных, 1–3 варианта и 2200 выходных токенов. Cloudflare rate limiter ограничивает запросы до 4/минуту на локацию, без гарантии глобального лимита расходов. Ошибка модели или лимита не заменяется фиктивной генерацией. Факты проверяет человек; инструкция модели не является гарантией отсутствия галлюцинаций.

Источники Cloudflare: [Workers AI bindings](https://developers.cloudflare.com/workers-ai/configuration/bindings/), [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [rate limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/). Бесплатная дневная квота не означает безлимитную бесплатность; платный тариф не включался этой доработкой.

## Следующий этап — предложение, пока не реализовано

Серверная сущность «Партия» с версиями предложения и отдельных черновиков → проверка требований категории → подтверждение состава и стоимости → очередь публикации → отчёт по каждому объявлению. Частичные ошибки и повтор запроса не должны создавать дубликаты. Изменение общего предложения предлагает обновить выбранные черновики, сохраняя индивидуальные правки. Публикация по городам должна учитывать правила Авито, не обходить ограничения массовыми копиями.

Открытый вопрос остаётся прежним: как правки внутри платформы возвращаются в подключённую таблицу и кто побеждает при одновременном изменении. Входящие изменения таблицы должны автоматически отражаться на платформе по решению владельца; текущая партия ещё не является такой интеграцией.

## Основной сценарий ИИ-генерации

По последнему запросу владельца экран открывается в режиме короткого задания. При описании задачи помощник выбирает до трёх прошлых объявлений по совпадениям слов. В режиме шаблона берёт выбранное объявление. Пользователь проверяет и может исправить заголовок, текст, города и цену перед согласованием. Цена и город из шаблона могут подставляться, недостающие параметры остаются на проверку.

После согласования запускается генерация обложки FLUX.1 Schnell на основе текста. Пользователь принимает её, запрашивает другую с дополнительным пожеланием или сохраняет исходные фотографии при наличии. Обложка создаётся по тексту объявления и пожеланиям. Фото шаблона можно сохранить вместе с обложкой. Черновик создаётся для каждого согласованного города. Ручной редактор и прежняя подготовка партий доступны отдельно. В защищённом превью черновики и картинки хранятся в памяти страницы.

## Доработка 21.11.2026

По обратной связи владельца обновлены постановка для текста, согласование и работа с фотографиями. Методика описаний и вариантов взята из [регламента автозагрузки](../../base/reglament-avtozagruzka) и [регламента объявлений](../../base/reglament-oformlenie-obyavleniy). Первые строки показывают пользу для ученика и следующий шаг. В готовый текст для каждого города подставляются фразы из конструкций `{вариант|вариант}`. Перед сохранением видно, сколько текстов получилось различными. Независимое предложение для одного города оценивает владелец, предупреждения о совпадениях требуют согласования.

Города предложены по контактам собственной истории, цена — медиана известных цен объявлений кабинета. Это ориентир по кабинету. Внешние данные по рынку и конкурентам пока не подключены. Проверки отмечают противоречия цены и формата, ограничения длины, контактные данные и совпадения с текстом или заголовком в том же городе.

После согласования текста сервис собирает обложку 4:3 с заголовком и выбранным фото из кабинета или загруженным фото репетитора. Это заменяет прежний шаг генерации абстрактной обложки. Фото сохраняет исходные пропорции. Сравнение с оригиналом и применение обложки доступны перед сохранением.

## Доработка 24.11.2026

Пустой запрос для выбранного шаблона сохраняет полный текст. При наличии запроса модель получает исходные абзацы и возвращает их точечные замены. Сервер сохраняет нетронутые блоки и проверяет, что правки не превратили описание в резюме. В режиме создания по брифу модель получает более полные примеры.

Готовые изображения можно выбрать из галереи и применить целиком. Для нового креатива пользователь загружает отдельный портрет, выбирает палитру и редактирует заголовок и короткую строку. FLUX генерирует фон, сервис собирает обложку 4:3 в браузере из фона, исходного портрета и набранного текста.
