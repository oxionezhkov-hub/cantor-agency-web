# Администрирование тестовых кабинетов

Владелец входит в `/admin` с отдельным паролем владельца. Список показывает существующие подключения из read-only привязки `CABINET_LEGACY_ACCOUNTS` и подключения, созданные в админке. Ответы API включают только ID, название, ID пользователя Авито и статус. Для нового подключения владелец вводит Client ID, Client Secret и ID пользователя. Ключи хранятся в зашифрованном виде с привязкой к ID кабинета. Проверка соответствия ключей аккаунту проходит первым шагом фоновой загрузки.

Активация сохраняет один кабинет и ставит задачу в очередь. Повтор использует ту же задачу. Ход работы, границы страниц, загруженные записи и момент следующей попытки сохраняются в SQLite Durable Object кабинета. После временной ошибки следующий запуск продолжает с сохранённого шага. Ручной повтор возобновляет остановленную загрузку. Одно срабатывание обрабатывает один шаг, до 25 записей на страницу, до 20 страниц на раздел или переписку и до 400 шагов на весь запуск. При достижении границы кабинет показывает частичный результат. Источник запрашивает официальные API Авито для объявлений, списка диалогов, истории сообщений, баланса и агрегатов за последние 14 завершённых московских суток. POST используется для OAuth и документированного чтения статистики.

Сотрудник входит по ссылке конкретного кабинета со своим логином и выданным паролем. Временный пароль действует 24 часа и разрешает только смену пароля. Сессия определяется на сервере, сброс и отзыв удаляют все сессии сотрудника. Роль «тестировщик» открывает разделы оболочки и позволяет пробовать локальные сценарии CRM и переписки в памяти вкладки. Передача сообщений в Авито и реальные операции с объявлениями, оплатой и настройками в тестовом контуре отсутствуют.

## Локальная проверка

Использовать отдельный `wrangler.cabinet-test.jsonc` и локальное хранилище. В этой конфигурации Worker использует только синтетические данные. Секреты локального запуска хранятся в игнорируемом `.dev.vars` или отдельном файле `--env-file`.

- `CABINET_OWNER_PASSWORD_SHA256` — SHA-256 отдельного пароля владельца.
- `CABINET_SESSION_SECRET` — случайный секрет для подписи cookie владельца.
- `CABINET_CONNECTION_KEY` — случайный ключ AES-256, 64 шестнадцатеричных символа.

Собрать через `npm run build:preview`, запустить `wrangler dev -c wrangler.cabinet-test.jsonc --local --port 8831`. Проверка `node scripts/ops/cabinet-local-check.mjs` принимает пароль через `CABINET_TEST_OWNER_PASSWORD` и проходит активацию, загрузку по alarm, смену пароля, сброс, отзыв и границы доступа двух кабинетов.

Подключение к реальному инвентарю требует отдельно настроенного окружения с `CABINET_SOURCE_MODE=avito` и read-only привязкой `CABINET_LEGACY_ACCOUNTS`. Синтетический Wrangler-конфиг не подключает боевые данные. Для использования реальных кабинетов требуется проверка доступности официальных методов и согласованный контур обработки этих данных.
