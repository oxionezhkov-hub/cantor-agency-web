# Синхронизация объявлений с таблицей

Прототип для отдельного тестового кабинета. Источник полей фида — Google Таблица. Список в Cantor читает её при открытии, каждые 30 секунд и по кнопке в «Автозагрузке». В списке открываются строки с уникальным `Id`, в том числе добавленные вручную в таблице. Сохранение новой карточки из Cantor добавляет одну строку. Редактор и массовая смена цены используют один серверный запрос и получают результат для каждой строки.

Сопоставление идёт по стабильному `Id` фида. Cantor создаёт его один раз перед отправкой формы. Повтор того же запроса обновляет состояние карточки без дубликата. Внешний ID Авито приходит отдельно из доверенной записи отчёта и показывается в карточке. Версия учитывает поля XML, доступность и папку фото. При несовпадении версии редактор показывает конфликт и даёт загрузить свежую версию. При сохранении из Cantor меняются только отредактированные ячейки. Статусы в Cantor включают отсутствие обязательных полей, ожидание автозагрузки, неподтверждённую запись, отказ и подтверждение Авито.

## Изолированная проверка

- Скопируйте шаблон BananLab в отдельную синтетическую таблицу. Укажите во второй строке `Id`, `Title`, `Description`, `Address`, `Category` и при необходимости `Price`, `Images`. В третьей строке пометьте поля, участвующие в XML, как «Грузим в XML». Ручная новая строка требует заполненного уникального `Id`.
- В отдельном проекте Apps Script подключите Advanced Google Service **Google Sheets API** и установите код из [ad-sync.gs](../../service-shell/scripts/sheets/ad-sync.gs). Ограничьте доступ к управлению скриптом и секретами. В Script Properties укажите `CANTOR_TEST_SHEET_ID`, `CANTOR_TEST_TAB`, случайный `CANTOR_SYNC_SECRET`. Для закрытого тестового веб-приложения Cantor укажите `AD_SHEET_TEST_URL` (адрес `/exec`) и такой же `AD_SHEET_TEST_SECRET` в окружении отдельного Worker. Прокси проверяет доступ к превью и same-origin для записи. Маршрут выключен без конфигурации.
- Для синтетической проверки подтверждения можно задать `CANTOR_TEST_REPORT_TAB`. В отчётной вкладке первая строка — заголовки, далее идут ID фида, версия, ID Авито, `applied` или `rejected`, причина. Сопоставляется последняя запись по ID фида; статус применяется только при совпадении версии строки. Храните отчётную вкладку под исключительным контролем интеграции. Сотрудники с правом менять отчёт могут изменить отображаемый статус.
- Команда `cd service-shell && node --test scripts/ops/ad-sheet-sync.test.mjs scripts/ops/preview-worker.test.mjs` проверяет сценарии на синтетической таблице и подменённом Google API. Настоящие Google Sheets и кабинет Авито в этой проверке не участвуют.

## Пределы прототипа

Записи Cantor в рамках одного Apps Script сериализованы. Google Sheets не предоставляет условной записи по версии ячейки, поэтому прямая правка человеком между контрольным чтением и записью всё ещё может пересечься с записью Cantor. Для допуска к рабочей таблице нужно согласовать механизм записи с атомарной проверкой версии либо ограничить редактирование служебных столбцов контролируемым путём.

Автоматической связи с формированием XML, сопоставлением версии XML с результатом Avito Upload ID и записью служебного статуса/ID в основной лист пока нет. Контур создания партии из ИИ и ручная проверка лайв-таблицы остаются отдельными этапами. Вручную созданный черновик вне подключённой таблицы работает по существующим правилам прототипа. Проверка категорий в этом прототипе базовая и не заменяет правила конкретной категории Авито.
