# Как подать заявку на приложение Авито

Инструкция для владельца Cantor · 20.11.2026

## Что нужно оформить

Для самостоятельного подключения других репетиторов нужно OAuth-приложение: каждый клиент разрешает ему доступ к своему кабинету на стороне Авито. Пароль профиля Авито в Cantor вводить не нужно. Для сопровождаемого пилота есть другой способ — персональные Client ID / Client Secret кабинета (client_credentials). Он не заменяет приложение для подключения других пользователей.

## Шаг 1. Войдите в основной профиль

Откройте https://www.avito.ru/ и войдите в профиль владельца будущего приложения. Для компании используйте основной аккаунт, а не аккаунт сотрудника. Не передавайте пароль и коды входа разработчику.

## Шаг 2. Откройте раздел приложений

Портал: https://www.avito.ru/developers . Ссылка регистрации, указанная в документации: https://developers.avito.ru/applications . Старый адрес может перенаправлять на новый портал.

Ищите «Мои приложения», затем добавление или регистрацию приложения. Точное расположение и названия кнопок сегодня не проверены: официальный портал из среды разработки не открылся. Это ориентир, а не гарантированный маршрут по экранам.

Если формы нет или требуется согласование, напишите в поддержку профессиональных инструментов Авито: supportautoload@avito.ru. Уточните порядок регистрации OAuth-приложения для SaaS, обслуживающего репетиторов в категории «Услуги». Персональные ключи своего кабинета выдаются отдельно: https://www.avito.ru/professionals/api .

## Шаг 3. Заполните основные поля

Название (пример): Cantor — кабинет репетитора.

Описание для копирования:

«Cantor — сервис для репетиторов, размещающих объявления на Авито. После явного разрешения владельца кабинета сервис показывает его объявления и статистику, помогает обрабатывать входящие обращения и учитывать запись на диагностику. Ответы отправляются в выбранном владельцем режиме: вручную, после согласования или автоматически. При первом подключении включён ручной режим. Запрашиваются только необходимые права, данные клиентов разделены, секреты хранятся на сервере. Изменение объявлений и продвижения не выполняется без отдельного разрешения пользователя.»

Это описание назначения. Если спрашивают готовность, укажите честно: «Есть защищённый прототип; промышленная интеграция разрабатывается и проверяется». Не называйте незапущенные функции действующими.

Redirect URI: постоянный HTTPS-адрес серверного обработчика кода авторизации на вашем домене. Шаблон: https://YOUR-DOMAIN.example/auth/avito/callback . Не отправляйте шаблон как рабочий адрес. Разработчик сначала должен реализовать обработчик и подтвердить фактическую ссылку. Главная страница и превью без callback не подходят. Рабочий callback Cantor сейчас не подтверждён.

Если форма просит сайт, контакт, юридические реквизиты, политику обработки данных, скриншоты или дополнительные документы — укажите фактические сведения. Обязательность этих дополнительных полей сегодня не проверена. Не выдумывайте реквизиты.

## Шаг 4. Выберите необходимые права

Для первой рабочей версии: user:read (профиль), items:info (объявления), stats:read (статистика), messenger:read (обращения), messenger:write (ответы и связанные действия).

По мере включения функций: autoload:reports (отчёты загрузки), user_balance:read (кошелёк), user_operations:read (операции). items:apply_vas запрашивайте при подключении управления продвижением. Не выбирайте все права заранее; права «Работы» и «Недвижимости» этому сценарию не нужны. Сопоставление новых методов со scopes сверяет разработчик по свежей спецификации.

Поле выбора прав может находиться в заявке либо настройках приложения. Точный интерфейс не проверен.

## Шаг 5. Отправьте заявку

Проверьте название, описание, контакты, рабочий HTTPS callback и права. Если есть действие «Запросить доступ» / «Отправить», отправьте самостоятельно. Сохраните номер, статус и ответ Авито. Срок рассмотрения и гарантия одобрения неизвестны.

Старые зеркала документации пишут «только доверенные партнёры»; более свежая копия этого условия не содержит. Ни свободное одобрение для всех, ни обязательный партнёрский статус сегодня напрямую не подтверждены. Если Авито запросит проверку партнёра, следуйте его ответу.

## Шаг 6. Передайте результат разработчику

Передайте Client ID, точный Redirect URI, разрешённые scopes и статус. Client Secret — только через согласованное защищённое хранилище. Не вставляйте его в чат, GitHub, PDF, скриншоты или браузерное хранилище.

Разработчик реализует проверку state, серверный обмен code на токены, безопасное обновление и отключение подключения. В исследованном руководстве access token действует 24 часа, refresh token — год; сервер должен учитывать фактический ответ и сохранять обновлённую пару.

## Шаг 7. Проверьте доступ клиента

Одобрение приложения не даёт каждому клиенту все методы. По исследованной документации для Messenger API в «Услугах» нужны подписки «Расширенный» или «Максимальный». Ключ сотрудника ограничен. Продвижение и аукцион могут требовать дополнительной доступности. Подписки Cantor и Авито — разные вещи.

Проверьте интеграцию на согласованном тестовом кабинете. Не отправляйте сообщения реальным покупателям ради проверки без отдельного разрешения.

## Что подтверждено и что не проверено

Основание: публичная копия официальной документации от 03.10.2026. В ней описаны два способа авторизации, название/описание приложения, HTTPS Redirect URI, согласие пользователя на scopes, access/refresh tokens и ограничения Messenger.

На 20.11.2026 напрямую не проверены: сегодняшняя форма, названия/расположение кнопок, дополнительные обязательные поля, критерии допуска, срок рассмотрения, реальный callback Cantor и права конкретного кабинета. Официальный портал не открылся из среды проверки (403/ошибка открытия). Эта инструкция не отправляет заявку.
