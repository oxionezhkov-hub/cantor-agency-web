# Прокси API Авито

`/api/avito/raw` передаёт запросы в API Авито от имени выбранного подключённого кабинета. Пароль передаётся в `x-dashboard-password`; действуют прежние правила `AVITO_API_PASSWORD` и пароля панели. Ключи Авито остаются на сервере.

## Методы и параметры

Поддерживаются **GET, POST, PUT, PATCH, DELETE**. Прокси не ограничен одним разделом API: объявления, продвижение, рассылки, чаты, автозагрузка, статистика и другие доступные кабинету операции используют тот же маршрут. Фактический доступ определяется правами приложения и ответом Авито; неизвестный или недоступный метод не становится доступным от наличия прокси.

| Параметр URL воркера | Назначение |
| --- | --- |
| `accountId` | ID подключённого кабинета |
| `path` | URL-encoded путь API Авито, включая его query-параметры |
| `allowWrite=true` | Явное разрешение на одну потенциально изменяющую операцию |

`{user_id}` и `{userId}` в пути заменяются ID выбранного кабинета. Разрешены только относительные пути API Авито. Запросы к `/token` через этот маршрут запрещены: авторизацией управляет воркер.

GET и POST из `AVITO_READ_POSTS` выполняются без `allowWrite`. В список чтения входят статистика рассылок, тариф и доступность рассылок, статистика объявлений, расходы, баланс, история операций, звонки и чаты CPA, цены продвижения, списки и статистика рекламных кампаний, вакансии, остатки и другие подтверждённые методы чтения. Неизвестные POST, PUT, PATCH и DELETE без флага возвращают `403 write_confirmation_required` до обращения к Авито. Проверка опирается на точный путь, а не на слова `get`, `info` или `stats` в произвольном URL.

Флаг не заменяет разрешение владельца на конкретную операцию. Например, запрос отчёта не разрешает отправлять сообщения, оплачивать рассылку или удалять объявления. Авито также использует POST для создания платных отчётов — такие операции требуют флага, даже если называются «получением отчёта».

## Статистика рассылок

Внешний запрос: `POST /api/avito/raw?accountId=<id>&path=%2Fspecial-offers%2Fv1%2Fstats`.

Тело запроса, например за завершённые дни ноября по Москве:

```json
{
  "dateTimeFrom": "2026-11-01T00:00:00+03:00",
  "dateTimeTo": "2026-11-22T23:59:59+03:00"
}
```

Ответ Авито находится в `data.stats`. Поля: дата отправки `sentAt`, окончание предложения `expiresAt`, объявление `itemId`, тип `offerSlug`, отправлено `count`, принято `accepted`, стоимость `price`. Принятое предложение не подтверждает продажу. Для отчёта сохраняйте строки по объявлениям; при объединении в запуски указывайте правило группировки. Для денежного пересчёта проверяйте единицы API. Календарь агентства и переписка — дополнительные источники, а не замена статистики Авито.

Официальная документация: <https://developers.avito.ru/api-catalog/sbc-gateway/documentation>.

## Тела запросов, ответы и ошибки

Тело передаётся без перекодирования вместе с `Content-Type`, включая multipart-загрузки. При необходимости передаётся `X-Source`. Входящий `Authorization` не пересылается: воркер использует токен выбранного кабинета.

Текстовый/JSON-ответ сохраняет прежний формат `{status, path, data}`. Для бинарных ответов добавляются `encoding: "base64"` и `contentType`, а `data` содержит base64. Пустой ответ Авито возвращается как пустая строка в `data`. Ошибки Авито сохраняют исходный статус в `status`; внешний HTTP-статус — 502.

Потенциальные записи не повторяются воркером после 429, 5xx или неопределённого сетевого сбоя и не переключаются на другой транспорт после такого сбоя. При исключении возвращается `outcome: "unknown"`: сначала проверьте состояние кабинета, затем решайте, нужен ли новый запрос. Российский прокси может обновить токен после явного отказа в авторизации; это не повтор после неопределённого результата записи.

## Публикация

Изменение `_worker.js` должно быть опубликовано в Cloudflare Worker `mainweb`. Текущий GitHub workflow `Deploy to hosting` исключает `_worker.js` из rsync: одно слияние PR само по себе не обновляет API воркера. Запросы нового метода до публикации будут получать старую ошибку `post_not_allowed`.
