# Скилл: структура сайта преподавателя на согласование

Мини-сервис: `site-structure/index.html` — одна страница-рендер для всех.
Наполнение каждого преподавателя — `site-structure/data/<slug>.json`.
Ссылка клиенту: `https://cantor.agency/site-structure/?client=<slug>`
(то же работает на воркере: `https://mainweb.oxion-ezhkov.workers.dev/site-structure/?client=<slug>`).

Без дизайна: чёрный, белый и оранжевый `#E8391D`. Картинки не вставляем —
пишем, какая картинка нужна (блок `image` / `images` / `video`).

## 1. Факты

Бриф — из CRM: `GET https://mainweb.oxion-ezhkov.workers.dev/api/crm/clients`,
у клиента `tasks.brief.comment` = `.../mba-mybrand?share=<id>`;
сам бриф: `GET /api/share?id=<id>` → `{ client.answers, schema }`
(ответы по `question.id` из `schema.blocks[].questions[]`).
Дополнительно — сценарии `podcast-scenarios/<Имя> — сценарий подкаст N.docx`.
Не выдумывать цифры, годы, названия — если нет, писать в `ask` («Нужно от вас»).

## 2. Набор блоков зависит от брифа

Референс порядка — сайты Анны Алёшиной (`client/anna-aleshina1..3`):
первый экран → проект/школа → обо мне (таймлайн) → подход → результаты →
отзывы → книги → интервью → контакты → подвал.

Сайт — про преподавателя как **предпринимателя** (как у Анны Алёшиной), а не
поиск учеников: первый экран «основатель / проекты / связаться», раздел
«Проекты», форма «Связаться» с темами для партнёров (партнёрство, инвестиции,
интервью, работа в команде, школа, другой вопрос).

**Никогда не ставим** (и не упоминаем даже в «Чего не будет на сайте»):
запись учеников на занятия, «Команда и работа в школе» (в т.ч. этапы отбора),
«Куда растёт школа» (планы, цифры роста). Пишем «Schoolsmart».

Источники кроме брифа — транскрибации подкастов
(`mba-mybrand/<slug>-podcastN-transkript.docx`) и сценарии.

Блок ставим, только если в брифе есть материал. Нет — переносим в `skipped`
с причиной («пришлите — добавим»). Примеры:
- книги/методички — только если есть; авторский курс можно поставить вместо книг;
- отзывы, результаты/кейсы — только если есть ссылки или истории;
- соцсети — только реально указанные (Instagram — с вопросом про пометку Meta);
- дипломы/сертификаты — если есть сканы или сильные сертификаты;
- «Подкасты» — всегда (3 подкаста МБА).

## 3. Формат JSON

```json
{ "slug", "name", "updated",
  "sections": [{ "id", "title", "purpose", "blocks": [..], "ask": [..] }],
  "skipped": [{ "title", "reason" }] }
```
Типы блоков (см. `BLOCKS` в `index.html`): `big`, `lead`, `text`, `h3`,
`buttons`, `stats`, `cards`, `list` (`negative: true` — «не подойду»),
`steps`, `timeline`, `quote`, `links`, `form`, `image`, `images`, `video`, `ask`.
Тексты — от первого лица, как будут стоять на сайте. Телефоны/почту в JSON
не пишем («номер из брифа») — файл публичный.

Проверка: `python3 -m http.server`, открыть `/site-structure/?client=<slug>`
на 1280 и 390 px, без горизонтального скролла и ошибок в консоли.

## 4. Реестр и CRM

Каждого нового клиента добавить в `site-structure/clients.json`:
`{ "slug", "name", "firstName", "crmIds": ["<id в CRM>", ...] }` (у одного человека
может быть две карточки в CRM — тогда оба id). По реестру работает вкладка
CRM «🌐 Структура сайтов» (`mba-mybrand/index.html`): ссылка, статус и готовое
сообщение для Telegram с кнопками «Скопировать».

Задача чек-листа `siteStructure` («Согласована структура сайта»). После мержа
и деплоя: свежий `GET /api/crm/clients` → взять `tasks` клиента целиком →
`tasks.siteStructure = { done: false, comment: <ссылка> }` → `PUT /api/crm/client
{ id, tasks }` → повторный GET и сверка `comment`. `done: true` ставит менеджер,
когда клиент согласовал. Подробности — `.claude/skills/podcast3-scenario/SKILL.md`, шаг 5.
