# Архитектурные паттерны

## Структура типичного сервиса

```
service/
├── src/
│   ├── api/          # Роуты, контроллеры
│   ├── domain/       # Бизнес-логика, сущности
│   ├── infra/        # БД, внешние сервисы, кэш
│   ├── shared/       # Утилиты, типы, ошибки
│   └── index.ts
├── tests/
└── config/
```

## Структура фронтенда (React/Next и аналоги)

```
app/
├── components/       # Переиспользуемые UI
├── features/         # Фичи (auth, dashboard, etc.)
├── lib/              # Клиенты, утилиты
├── hooks/
└── types/
```

## Рекомендуемые подходы

### API
- Версионирование с самого начала (`/v1/`)
- Единый формат ошибок
- Идемпотентные POST где возможно (с ключами)
- Пагинация курсорная или offset с лимитами

### Данные
- Явные типы/схемы на границах
- Отдельные DTO для API и доменных сущностей
- Миграции вместо ручных изменений схемы

### Ошибки
- Доменные ошибки vs инфраструктурные
- Не показывать внутренние детали клиенту
- Логировать с контекстом (request id, user id)

## Антипаттерны, которых избегать

- God-объекты и God-компоненты
- Бизнес-логика в контроллерах / компонентах
- Прямые вызовы БД из UI-слоя
- Жёстко зашитые конфиги вместо переменных окружения
- Отсутствие границ ответственности
