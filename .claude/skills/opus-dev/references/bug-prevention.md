# Предотвращение багов

## Типичные источники багов в сервисах и сайтах

### Валидация и границы
- Отсутствие проверки типов и диапазонов
- Необработанные пустые массивы / null
- Off-by-one ошибки в пагинации и циклах
- Неправильная обработка timezone и дат

### Состояние и конкурентность
- Race conditions при параллельных запросах
- Устаревшее состояние в UI
- Неправильный cleanup в useEffect / подписках
- Проблемы с кэшем и инвалидацией

### Ошибки и отказоустойчивость
- Необработанные промисы (unhandled rejection)
- Молчаливое проглатывание ошибок
- Отсутствие таймаутов на внешние вызовы
- Неправильные retry-логики (бесконечные циклы)

### Безопасность
- SQL/NoSQL injection
- XSS через неэкранированный пользовательский ввод
- Утечка секретов в логах или клиентском коде
- Неправильная проверка прав (IDOR)

### Frontend-специфика
- Отсутствие loading и error состояний
- Проблемы с гидрацией (SSR)
- Утечки памяти из-за незакрытых слушателей
- Неправильная работа с формами (двойная отправка)

## Обязательный мини-чеклист перед сдачей

1. Все внешние данные валидируются?
2. Что произойдёт при сетевой ошибке?
3. Есть ли обработка пустого результата?
4. Секреты не попали в клиент?
5. Можно ли сломать это быстрым двойным кликом / повторным запросом?
6. Логика читается без комментариев?

## Правило 3 вопросов
Перед сдачей кода задай себе:
- Что сломается первым при реальном использовании?
- Как пользователь поймёт, что что-то пошло не так?
- Что будет, если этот код вызовут дважды одновременно?
