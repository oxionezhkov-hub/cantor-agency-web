# Стандарты качества кода

## Общие правила

- **Ясность > краткость.** Лучше чуть длиннее, но понятно.
- Имена говорят сами за себя. Избегай `data`, `info`, `temp`, `helper`.
- Функции делают одну вещь.
- Ранний возврат вместо глубокой вложенности.
- Константы вместо магических чисел и строк.

## Обработка ошибок

```ts
// Хорошо
try {
  const result = await riskyOperation();
  return result;
} catch (error) {
  logger.error("Failed to do X", { error, context });
  throw new DomainError("Не удалось выполнить операцию", { cause: error });
}
```

## Валидация

Всегда валидируй на входе в систему (API, формы, очереди).

## Тестируемость

- Зависимости инжектируются или легко мокаются.
- Чистые функции где возможно.
- Побочные эффекты изолированы.

## Что считать «готовым»

Код считается готовым только когда:
- Прошёл мысленный прогон основных и крайних сценариев
- Есть понимание, как его протестировать
- Обработаны очевидные ошибки
- Не содержит TODO без объяснения
