# Скилл: генерация сценария «Подкаст 3» (для учеников/родителей) + подключение в CRM

Репозиторий: `oxionezhkov-hub/cantor-agency-web` (GitHub).
Ветка по умолчанию: `main`.
Файлы сценариев лежат плоско в папке `podcast-scenarios/` в корне репо.

Это адаптация уже отработанного процесса генерации «Подкаста 2» (см.
`.claude/skills/podcast2-scenario/SKILL.md`, если есть, либо соседний файл
в аплоадах) — тот же пайплайн docx → git → PR → CRM, но другая аудитория
и другая структура интервью.

## 0. Вход в задачу

Тебе дают одно или несколько имён. Для каждого имени в репозитории уже
должны существовать файлы:

```
podcast-scenarios/<Имя Фамилия> — сценарий подкаст 1.docx
podcast-scenarios/<Имя Фамилия> — сценарий подкаст 2.docx   (если есть)
```

Нужно сделать:

```
podcast-scenarios/<Имя Фамилия> — сценарий подкаст 3.docx
```

— интервью **для учеников и их родителей** (потенциальных и текущих),
которое раскрывает участника подкаста как преподавателя/наставника:
как у него выстроен процесс обучения, как проходят занятия, какие
результаты у учеников, чем он гордится, какие у него сильные стороны и
над чем он ещё работает, почему он любит своё дело, почему его подход/его
преподаватели — одни из лучших.

Если имя не находится точным поиском — искать по фамилии
(`ls podcast-scenarios | grep -i Фамилия`), в репозитории встречаются
варианты написания фамилий.

## 1. Собрать факты

Источники — **бриф героя и уже существующие сценарии** (в первую очередь
подкаст 1, и подкаст 2, если он есть). Сценарии — `.docx`, вытаскиваем
текст через `unzip` + `word/document.xml` (быстрее и надёжнее pandoc,
который в этом окружении может отсутствовать):

```bash
mkdir -p /tmp/p1/<slug>
unzip -oq "podcast-scenarios/<Имя Фамилия> — сценарий подкаст 1.docx" -d /tmp/p1/<slug>

python3 - <<'EOF'
import re
xml = open("/tmp/p1/<slug>/word/document.xml", encoding='utf-8').read()
paras = re.findall(r'<w:p[ >].*?</w:p>', xml, re.S)
out = []
for p in paras:
    texts = re.findall(r'<w:t[^>]*>(.*?)</w:t>', p, re.S)
    out.append(''.join(texts))
print('\n'.join(out))
EOF
```

Повторить то же для сценария подкаст 2 (если файл существует для героя).

Из обоих источников выписать:
- имя, роль, название школы/проекта, предмет/направление;
- как устроен процесс обучения: структура урока, методика, что происходит
  на занятии от начала до конца;
- конкретные результаты учеников — цифры, кейсы, конкурсы/экзамены/олимпиады,
  истории «было — стало»;
- чем герой гордится больше всего (конкретный кейс или принцип, а не общие слова);
- его сильные стороны как преподавателя — по его же словам или по описанию
  методики/подхода в брифе;
- над чем он сам ещё работает / что развивает в себе или в методике —
  честный, не глянцевый ответ;
- почему он любит свою работу — личная мотивация, а не декларация;
- почему его подход/его преподаватели — одни из лучших: что отличает от
  других школ/репетиторов (индивидуализация, обратная связь родителям,
  подбор методики под ребёнка и т.п.).

Если каких-то фактов не хватает — не выдумывать цифры и кейсы; формулировать
вопрос так, чтобы герой сам их назвал в интервью (открытый вопрос вместо
готового утверждения).

## 2. Структура сценария 3 (шаблон)

Аудитория: **ученики и родители** (действующие и потенциальные — те, кто
выбирает, к кому отдать ребёнка/пойти учиться сами).
Хронометраж: **20–25 минут**. Тон: **тёплый, живой, вызывающий доверие**,
чуть более личный и эмоциональный, чем в подкасте 2 (там аудитория —
кандидаты в сотрудники, тут — семьи, которые доверяют ребёнка).
Ведущий, как и в подкасте 2, **лично с героем не знаком** — работает в
смежной сфере (например, ведёт образовательные подкасты), и разговор
должен звучать естественно и для случайного слушателя.

**Важно про формулировки вопросов**: никогда не пиши в вопросе оценочные
утверждения о госте («я знаю, что вы прекрасный педагог») — веди к тому
же через открытый вопрос («Что для вас значит быть хорошим педагогом?»,
«Как вы понимаете, что урок прошёл хорошо?»).

**Структура — 5 блоков, 12 вопросов** (2+3+3+2+2), под каждым вопросом —
курсивная подсказка (1 строка: что вытащить этим вопросом и зачем это
аудитории учеников/родителей):

1. **ЗНАКОМСТВО — Кто перед вами** (2 вопроса)
   - простой открывающий вопрос: кто герой, чем занимается, кого и чему учит;
   - почему он вообще выбрал преподавание/это направление — личная история,
     точка входа в профессию.

2. **КАК УСТРОЕНО ОБУЧЕНИЕ — Взгляд изнутри урока** (3 вопроса, приоритетный блок)
   - как выглядит типичное занятие от начала до конца — что делает урок
     именно его уроком, а не «уроком вообще»;
   - как он подбирает подход/темп под конкретного ребёнка — гибкость
     системы;
   - как выглядит обратная связь для ученика и родителя — как узнают,
     что прогресс есть.

3. **РЕЗУЛЬТАТЫ И ГОРДОСТЬ — Что получают ученики** (3 вопроса, приоритетный блок)
   - самый сильный кейс/история ученика (из брифа/сценариев) — что
     изменилось и что в подходе педагога это дало;
   - чем он гордится больше всего в своей работе — не общими словами,
     а конкретным моментом или принципом;
   - какой результат для него самый ценный — не обязательно оценки/баллы
     (может быть уверенность ребёнка, любовь к предмету и т.п.).

4. **ЧЕЛОВЕК ЗА МЕТОДИКОЙ — Сильные стороны и рост** (2 вопроса)
   - в чём его сильная сторона как преподавателя, по его же ощущению;
   - над чем он сам продолжает работать/учиться — честный, небанальный ответ
     про рост, а не декларация идеальности.

5. **ПОЧЕМУ ИМЕННО ЗДЕСЬ — Обращение к родителям и ученикам** (2 вопроса)
   - почему он любит то, чем занимается — что заряжает именно в этой профессии;
   - прямое обращение: что он говорит семье, которая выбирает, к кому пойти —
     чем этот выбор оправдан.

Перед блоками — раздел **«КАК РАБОТАТЬ С ЭТИМ ДОКУМЕНТОМ»** (только для
ведущего, без пунктов про монтаж/SEO/клипы), стандартный текст:

```
• Тон разговора — тёплый, живой, вызывающий доверие. Задача — чтобы родитель или ученик, послушав, почувствовал, что понимает, к кому идёт учиться.
• Вопросов ровно на хронометраж — старайтесь пройти все, не затягивая ответы.
• Если ответ звучит слишком общо (пример из брифа героя в кавычках) — попросите конкретный пример, историю ученика или случай с урока.
• Блоки 2 и 3 (как устроено обучение и результаты) — приоритетные, им можно уделить чуть больше времени за счёт остальных.
```

## 3. Генерация .docx (docx-js)

Формат должен визуально совпадать с уже существующими сценариями подкаста 2
(тот же стиль, только слова «сотрудников» на «учеников и родителей» и т.д.).
Точная разметка (совпадает с эталоном подкаста 2, кроме подписи блока):

- Заголовок «СЦЕНАРИЙ ИНТЕРВЬЮ» — по центру, bold, size 32 (= 16pt).
- Подзаголовок «<Имя> — <роль>, <проект/школа>» — по центру, italic, size 22.
- «Подкаст для учеников и родителей» — по центру, italic, size 22.
- «Хронометраж: 20–25 минут  •  Формат: тёплый, доверительный разговор» — по центру, size 20.
- «КАК РАБОТАТЬ С ЭТИМ ДОКУМЕНТОМ» — bold, size 24.
- Пункты подсказок — indent left 200, size 22, префикс `• `.
- Заголовок блока «БЛОК N. …» — HeadingLevel.HEADING_1, bold, size 26, spacing before 400.
- «Цель: …» под заголовком блока — italic, size 22, spacing after 200.
- Вопрос — indent left 200, **bold**, size 22, префикс `• `, spacing after 40.
- Подсказка под вопросом — indent left 200, italic, size 20, spacing after 220.

Рабочий скрипт (Node, пакет `docx` — если не установлен: `npm install docx` в
scratchpad-директории, не в самом репозитории):

```js
// gen.js
const fs = require('fs');
const path = require('path');
const { Document, Packer, Paragraph, TextRun, HeadingLevel, AlignmentType } = require('docx');

function titleBlock(subtitle) {
  return [
    new Paragraph({ alignment: AlignmentType.CENTER, spacing: { after: 100 },
      children: [new TextRun({ text: 'СЦЕНАРИЙ ИНТЕРВЬЮ', bold: true, size: 32 })] }),
    new Paragraph({ alignment: AlignmentType.CENTER, spacing: { after: 60 },
      children: [new TextRun({ text: subtitle, italics: true, size: 22 })] }),
    new Paragraph({ alignment: AlignmentType.CENTER, spacing: { after: 60 },
      children: [new TextRun({ text: 'Подкаст для учеников и родителей', italics: true, size: 22 })] }),
    new Paragraph({ alignment: AlignmentType.CENTER, spacing: { after: 300 },
      children: [new TextRun({ text: 'Хронометраж: 20–25 минут  •  Формат: тёплый, доверительный разговор', size: 20 })] }),
  ];
}

function howToWork(tips) {
  const paras = [new Paragraph({ spacing: { after: 100 },
    children: [new TextRun({ text: 'КАК РАБОТАТЬ С ЭТИМ ДОКУМЕНТОМ', bold: true, size: 24 })] })];
  tips.forEach((t) => paras.push(new Paragraph({ indent: { left: 200 }, spacing: { after: 100 },
    children: [new TextRun({ text: '• ' + t, size: 22 })] })));
  return paras;
}

function block(title, goal, questions) {
  const paras = [
    new Paragraph({ heading: HeadingLevel.HEADING_1, spacing: { after: 60, before: 400 },
      children: [new TextRun({ text: title, bold: true, size: 26 })] }),
    new Paragraph({ spacing: { after: 200 },
      children: [new TextRun({ text: 'Цель: ' + goal, italics: true, size: 22 })] }),
  ];
  questions.forEach((q) => {
    paras.push(new Paragraph({ indent: { left: 200 }, spacing: { after: 40 },
      children: [new TextRun({ text: '• ' + q.q, bold: true, size: 22 })] }));
    paras.push(new Paragraph({ indent: { left: 200 }, spacing: { after: 220 },
      children: [new TextRun({ text: q.hint, italics: true, size: 20 })] }));
  });
  return paras;
}

const DEFAULT_TIPS = [
  'Тон разговора — тёплый, живой, вызывающий доверие. Задача — чтобы родитель или ученик, послушав, почувствовал, что понимает, к кому идёт учиться.',
  'Вопросов ровно на хронометраж — старайтесь пройти все, не затягивая ответы.',
  'Если ответ звучит слишком общо — попросите конкретный пример, историю ученика или случай с урока.',
  'Блоки 2 и 3 (как устроено обучение и результаты) — приоритетные, им можно уделить чуть больше времени за счёт остальных.',
];

function buildDoc(spec) {
  const children = [
    ...titleBlock(spec.subtitle),
    ...howToWork(spec.tips || DEFAULT_TIPS),
    ...spec.blocks.flatMap((b) => block(b.title, b.goal, b.questions)),
  ];
  return new Document({ sections: [{ properties: {}, children }] });
}

const specs = require('./scenarios-data.js'); // массив спецификаций, см. ниже

(async () => {
  const outDir = path.join(__dirname, 'out');
  fs.mkdirSync(outDir, { recursive: true });
  for (const spec of specs) {
    const doc = buildDoc(spec);
    const buf = await Packer.toBuffer(doc);
    fs.writeFileSync(path.join(outDir, `${spec.fileName}.docx`), buf);
    console.log('written', spec.fileName);
  }
})();
```

`scenarios-data.js` — массив объектов вида:

```js
module.exports = [
  {
    fileName: 'Имя Фамилия — сценарий подкаст 3',
    subtitle: 'Имя Фамилия — <роль>, <название школы/проекта>',
    blocks: [
      { title: 'БЛОК 1. ЗНАКОМСТВО — Кто перед вами', goal: '...', questions: [
        { q: '...', hint: '...' },
        { q: '...', hint: '...' },
      ]},
      // БЛОК 2..5 по структуре из раздела 2 (3+3+2+2 вопроса)
    ],
  },
  // ещё герои...
];
```

Запуск: `node gen.js` → файлы появятся в `./out/`.

## 5. Подключить ссылку в CRM (без доступа к самой CRM UI!)

CRM — это Cloudflare Worker (`mainweb`) поверх KV-namespace `MBA_MYBRAND_KV`.
Продакшн API доступен напрямую и **без авторизации**:

- База: `https://mainweb.oxion-ezhkov.workers.dev` (можно и через прод-домен
  `https://cantor.agency`, обычно эквивалентно).
- Список клиентов CRM: `GET /api/crm/clients` → `{ clients: [...], checklist: [...] }`.
- Обновление клиента: `PUT /api/crm/client` с телом
  `{ "id": "<clientId>", "tasks": <полный объект tasks клиента> }`.
  **Важно**: `tasks` подставляется целиком (через `sanitizeCrmTasks`), поэтому
  нужно взять текущий `tasks` клиента, точечно поменять нужное поле и
  отправить весь объект обратно — иначе остальные задачи (даты записи,
  ссылки на запись, монтаж и т.д.) обнулятся.

**Свежесть чтения перед записью (обязательно для каждого клиента отдельно)**:
CRM редактируется вручную через UI параллельно с этим процессом (например,
дату записи могли проставить прямо сейчас). Поэтому нельзя переиспользовать
один закешированный `GET /api/crm/clients`, снятый в начале скрипта, для
записи нескольких клиентов подряд — окно между чтением и записью должно быть
минимальным:
1. Прямо перед `PUT` для конкретного клиента — свежий `GET /api/crm/client/<id>`
   (или свежий `GET /api/crm/clients`, если поштучного эндпоинта нет) —
   не переиспользовать JSON, снятый на шаге поиска client id.
2. Взять `tasks` из этого свежего ответа, точечно поменять `podcast3.script`,
   тут же отправить `PUT`.
3. Сразу после `PUT` — ещё раз `GET` того же клиента и явно сверить, что
   `tasks.podcast3.script.comment` в ответе равен записанной ссылке. Считать
   шаг успешным только по этой проверке, а не по `"ok":true` в ответе `PUT`
   (это подтверждает, что запрос принят, а не что нужное поле реально
   сохранилось — оно могло быть перезаписано конкурентной правкой из UI
   до момента проверки).
4. Повторить 1–3 для каждого клиента по отдельности, не пакетно.

Структура задачи `tasks.podcast3.script`:
```json
{ "done": true, "comment": "https://cantor.agency/podcast-scenarios/<url-encoded filename>.docx" }
```
(аналогично `tasks.podcast1.script` / `tasks.podcast2.script` — так CRM
уже хранит ссылки на сценарии, это подтверждённый существующий паттерн).
Если в объекте `tasks` клиента ещё нет ключа `podcast3` — создать его как
`{ "script": {...} }`, не трогая остальные существующие ключи.

Ссылка на файл — публичный URL сайта + `%`-энкодинг имени файла
(включая пробелы как `%20` и тире `—` как `%E2%80%94`):
```
https://cantor.agency/podcast-scenarios/<urllib.parse.quote(filename, safe='')>
```

### Практический скрипт (Python, через curl)

```python
import json, urllib.parse, subprocess

CRM_LIST = 'https://mainweb.oxion-ezhkov.workers.dev/api/crm/clients'
CRM_PUT = 'https://mainweb.oxion-ezhkov.workers.dev/api/crm/client'

def fetch_clients():
    r = subprocess.run(['curl', '-s', CRM_LIST], capture_output=True, text=True)
    return {c['id']: c for c in json.loads(r.stdout)['clients']}

# 1. Найти client id по имени (из брифа) — ФИО в CRM часто отличается от
#    короткого имени в файле сценария, сопоставлять по фамилии.
#    Этот снимок годится только для поиска id, НЕ для записи ниже.
by_id = fetch_clients()
for c in by_id.values():
    if 'Фамилия' in c['name']:
        print(c['id'], c['name'])

# 2. Обновить нужных клиентов — по одному, с точечным чтением перед записью
mapping = {
  '<clientId1>': 'Имя Фамилия — сценарий подкаст 3.docx',
  # ...
}
for cid, fname in mapping.items():
    url = 'https://cantor.agency/podcast-scenarios/' + urllib.parse.quote(fname, safe='')

    # 2a. Свежий GET прямо перед записью — не переиспользуем by_id сверху
    fresh = fetch_clients()
    c = fresh[cid]
    tasks = json.loads(json.dumps(c['tasks']))  # deep copy
    tasks.setdefault('podcast3', {})
    tasks['podcast3']['script'] = {'done': True, 'comment': url}
    payload = {'id': cid, 'tasks': tasks}

    # 2b. Запись
    res = subprocess.run(
        ['curl', '-s', '-X', 'PUT', CRM_PUT,
         '-H', 'Content-Type: application/json', '-d', json.dumps(payload, ensure_ascii=False)],
        capture_output=True, text=True)

    # 2c. Верификация — перечитать и явно сверить сохранённое значение,
    #     не полагаться на "ok":true из ответа PUT
    verify = fetch_clients()[cid]
    saved = verify['tasks'].get('podcast3', {}).get('script', {}).get('comment')
    ok = saved == url
    print(cid, c['name'], 'PUT ok:', '"ok":true' in res.stdout, 'verified:', ok)
    if not ok:
        print('  MISMATCH — saved:', saved, 'expected:', url)
```
