# Скилл: страница «Подкаст + Статья + посты + Транскрибация» по мотивам подкаста

## Коротко

**Вход:** эмбед видео подкаста (Vimeo iframe-код или ссылка) + транскрибация
разговора (готовый текст, либо сырая запись — тогда сначала расшифровать).

**Что делать:** скопировать страницу Ивана Хлебникова как шаблон
(`mba-mybrand/ivan-hlebnikov-podcast1`), вставить новый эмбед, написать под
героя пять типов текста — карточку для публикации видео, статью-колонку,
5 постов для Telegram и размеченную транскрибацию (см. шаги 1–4 ниже) —
и собрать из этого страницу того же вида под новым именем файла.

**Выход:** ссылка на готовую страницу
(`https://cantor.agency/mba-mybrand/<slug>-podcastN`) — отдать её как
результат, и та же ссылка добавляется в CRM mba-mybrand, в карточку
клиента, в подзадачу «Сделаны тексты» нужного подкаста (шаг 7).

Работает для любого героя и любого из трёх подкастов (репетиторы,
преподаватели, эксперты — кто угодно, у кого есть бриф в CRM mba-mybrand).

---

Референс — уже готовая страница, сделанная по этому пайплайну:
`mba-mybrand/ivan-hlebnikov-podcast1` → https://cantor.agency/mba-mybrand/ivan-hlebnikov-podcast1

Репозиторий: `oxionezhkov-hub/cantor-agency-web`. Ветка по умолчанию: `main`.
Файл — плоский, без расширения, лежит в каталоге `mba-mybrand/`:

```
mba-mybrand/<slug>-podcastN
```

`<slug>` — имя и фамилия героя латиницей через дефис, транслитерация
(«Иван Хлебников» → `ivan-hlebnikov`). `N` — номер подкаста, **тот же**,
что и в чек-листе CRM (`podcast1` / `podcast2` / `podcast3` — см. `CRM_CHECKLIST`
в `_worker.js`) и в теме интервью:
- **podcast1** — бизнес-история для партнёров/предпринимателей (как в
  референсе: путь героя, философия, деньги, управление);
- **podcast2** — рекрутинговый, про найм, для потенциальных сотрудников;
- **podcast3** — для учеников/родителей, см. `.claude/skills/podcast3-scenario/SKILL.md`.

Не путай это с версией видеофайла в названии эмбеда (`_v1`/`_v2`/… в title
у Vimeo-плеера) — это просто номер монтажной версии, к номеру подкаста
и аудитории отношения не имеет. Аудиторию и номер подкаста уточняй у
команды/по брифу, а не угадывай по имени файла.

Файл отдаётся как обычная HTML-страница на
`https://cantor.agency/mba-mybrand/<slug>-podcastN` — так же, как уже
отдаются `offer`, `client/iulia-yanson`, `podcast-scenarios/...` и т.п.
Отдельная маршрутизация для конкретного имени файла не нужна.

⚠️ **Важно про архитектуру:** прод (`cantor.agency`) отдаётся напрямую
через nginx (DNS домена — на reg.ru, не на Cloudflare), а не через
Cloudflare Worker — `_worker.js` реально исполняется только на
`*.workers.dev` (в т.ч. превью-домены веток) и обслуживает там `/api/*`
и раздачу ассетов. На проде для плоского файла (`mba-mybrand/<slug>-podcastN`)
это не имеет значения — nginx просто отдаёт файл по точному пути. Но для
самого каталога `mba-mybrand/` без имени файла (`/mba-mybrand` и
`/mba-mybrand/`) nginx резолвит индекс сам, только если там лежит файл
`index.html` (или `index.htm`) — **не** `index` без расширения. Поэтому:

⚠️ `mba-mybrand/index.html` — это CRM/анкета-бриф самого агентства
(открывается по `/mba-mybrand`). Никогда не перезаписывай, не удаляй и не
переименовывай этот файл (расширение `.html` обязательно — без него прод
отдаёт 403 на `/mba-mybrand/`) — только добавляй рядом файлы
`<slug>-podcastN[...]`. В `_worker.js` есть дублирующий рерайт
`/mba-mybrand` и `/mba-mybrand/` → `/mba-mybrand/index.html` для домена
воркера — держи его в синхроне с именем файла, если когда-нибудь его
переименуешь.

## 0. Вход в задачу

На входе: имя героя, номер подкаста (1/2/3 — определяет аудиторию и тему),
чем занимается/какой бизнес, и материал —
- уже готовая текстовая транскрибация подкаста, ИЛИ
- сырая запись (аудио/видео) — тогда сначала расшифровать:
  `mcp__transcribe_video__transcribe_video`, либо, если запись лежит в
  Descript-проекте, `mcp__Descript__export_transcript`.

Ведущий подкаста в транскрибации почти всегда один и тот же человек;
если его личное имя не важно для клиента — подписывай реплики просто
«Ведущий» (как в референсе), а не именем сотрудника агентства. Реплики
героя идут под его настоящим именем.

Если у эпизода есть готовое смонтированное видео на Vimeo — понадобится
его прямая ссылка на просмотр (`https://vimeo.com/<id>`, не embed-ссылка
плеера) для кнопки скачивания.

Результат на выходе — один файл `mba-mybrand/<slug>-podcastN` с четырьмя
типами контента внутри, переключаемыми табами:
1. **Подкаст** — карточка для публикации видео (название/описание/ключевые
   слова/хэштеги, каждый блок копируется отдельно) + кнопка скачивания видео;
2. **Статья** — колонка от первого лица;
3. **Посты для Telegram** — обычно 5 шт., пронумерованные;
4. **Транскрибация** — полный разговор, разбитый на тематические разделы
   с оглавлением.

Плюс два `.docx`-файла рядом (`<slug>-podcastN-statya.docx`,
`<slug>-podcastN-transkript.docx`) и отметка в CRM (шаг 7).

## 1. Разметить транскрибацию на разделы

Перечитать сырой текст разговора целиком и разбить его на 12–20 смысловых
блоков (в референсе — 17), каждый с коротким названием («Найм и обучение
преподавателей», «Критика против требовательности» и т.п.). Это станет
оглавлением (`.tr-toc`) и якорями `#t1`, `#t2`, … в транскрибации.

Внутри раздела реплики оформляются построчно, без пересказа и без купюр
смысла — можно только:
- убрать слова-паразиты, повторы, сбивки речи;
- склеить сильно рубленые фразы в связный письменный текст;
- убрать откровенно нерелевантные технические реплики (проверка звука и т.п.).

Менять факты, цифры, формулировки позиции героя — нельзя. Транскрибация —
это источник правды, на который потом опираются статья, посты и карточка
подкаста.

## 2. Написать статью (колонка от первого лица)

- Объём: не жалей материала — в референсе статья выросла до 14 разделов
  и покрывает практически всю фактуру транскрибации. Лучше больше и подробнее,
  чем куцая колонка на 700 слов.
- Заголовок (`h1`) — не описательный, а с крючком/поворотом («От зала суда
  до урока гитары: как я построил две школы и зачем мне это нужно»). Никакой
  строки-подписи под заголовком («Колонка от первого лица · Имя — роль») —
  просто заголовок и сразу текст.
- 10+ подзаголовков (`h2`), которые идут по драматургии разговора:
  предыстория → точка выбора → философия/принципы → как устроено дело
  сейчас (с конкретными цифрами — трафик, штат, выручка, если герой их
  называл) → чего не хватает/уязвимости → куда идёт дальше → личный штрих
  (книги/фильмы/контакты) в самом конце. Сюжет статьи можно перестроить
  свободно, лишь бы вся фактура была из транскрибации.
- Один `blockquote` с самой сильной, афористичной цитатой героя.
- Текст — от первого лица, разговорный, но письменный (не транскрибационный
  синтаксис). Заканчивается подписью героя (`class="art-signature"`):
  имя + должность/роль.

## 3. Написать посты для Telegram (обычно 5)

Каждый пост — самостоятельный, читается и копируется отдельно от остальных,
без отсылок «как я говорил в посте выше». Берём 5 самых ярких, законченных
кусков смысла из транскрибации — по одному тезису/истории на пост.

Структура одного поста (`.tg-card` → `.tg-body`) — **пишем как реальный
Telegram-пост**, без веб-вёрстки:
- заголовок-хук с эмодзи прямо в тексте (`h3`, но без крупного шрифта и
  цвета — просто жирный текст того же кегля, что и остальной пост:
  «🚫 Мы официально запретили критику в школе. Вот что из этого вышло»);
- первая строка-крючок (1 предложение, задаёт интригу/парадокс);
- тело: при необходимости 1–2 подзаголовка (`h4`) для двух смысловых частей
  («Что мы сделали вместо этого», «Личная история») — тоже без цвета,
  жирным, можно курсивом;
- закрывающая строка — афоризм/вывод/призыв.
- **Никакого** `.tg-tag` (рубрика-плашка под шапкой) и никакого красного
  цвета/крупных заголовков внутри поста — только `<strong>`/`<em>` и обычный
  текст. Списки — простым текстом (эмодзи-нумерация или тире), без `<ul>/<ol>`
  с маркерами: в Telegram такого форматирования всё равно нет.
- В шапке карточки (`.tg-topbar`) — короткая тема поста вместо технической
  подписи («Пост про философию обучения», а не «Telegram · пост 1 из 5») и
  кнопка «Копировать текст» (`.copy-btn`, `data-copy="copyN"`) — работает
  через общий JS в шаблоне, нужно только проставить `id="copyN"` на
  `.tg-body` с тем же номером.

Названия табов для постов (`data-tab="post1"` и т.д., вторая строка меню) —
просто «Пост 1» … «Пост N», без темы и без эмодзи-нумерации — тема уже
написана в шапке самой карточки.

## 4. Собрать карточку «Подкаст» (публикация видео)

Аудитория выпуска (партнёры/сотрудники/клиенты — по факту от команды, не
по номеру в имени видеофайла) подписана **не в самой панели**, а в плашке
`.intro-badge` в самом верху страницы: «Материалы подкаста для
<аудитория>» — замени там дефолтный текст «Материалы подкаста».

Первая вкладка (`#podcast`), открыта по умолчанию. Сверху вниз:
1. **Сам эмбед** (`.podcast-video-block` → `.video-wrap` с `padding:56.25% 0 0 0`
   + iframe `player.vimeo.com/video/<id>?title=0&byline=0&portrait=0&badge=0…`
   + `<script src="https://player.vimeo.com/api/player.js">`).
2. **Строка `.podcast-dl-row`, под видео** — слева кнопка «Скачать видео»
   (`.dl-btn.podcast-dl-btn`, на половину ширины блока) со ссылкой на
   `https://vimeo.com/<id>` (страница просмотра, НЕ embed-URL, target="_blank"),
   справа — короткая подсказка (`.podcast-dl-hint`), что делать дальше:
   «Нажмите на кнопку, перейдите на страницу видео на Vimeo и под видео
   нажмите на кнопку скачивания подкаста».
3. **Карточка полей** (`.doc-card`) — каждое поле в своём `.kit-head`
   (`<h3>` + маленькая кнопка `copy-btn on-light`, копирует именно это
   поле, а не всю карточку разом):
   - Название видео;
   - Описание (с эмодзи-плейсхолдерами под ссылки: `🔗 ...: [ссылка]`);
   - Ключевые слова;
   - Хэштеги.
   **Без блока «Таймкоды»** — не добавляй его, если явно не попросили.

## 5. Собрать HTML-файл

Не писать вёрстку заново — копировать `mba-mybrand/ivan-hlebnikov-podcast1`
как шаблон и менять контент, а не структуру/CSS/JS:

1. `cp mba-mybrand/ivan-hlebnikov-podcast1 mba-mybrand/<slug>-podcastN`
2. `<title>` — заменить имя героя.
3. `.intro-badge` (плашка в самом верху страницы) — «Материалы подкаста
   для <аудитория>» вместо дефолтного текста (см. шаг 4).
4. Меню разделов (`.tabs-row1`): «Подкаст» / «Статья» / «Транскрибация» —
   иконки инлайн-SVG (плей / документ / микрофон), не эмодзи; меню
   отцентровано (`.tabs{justify-content:center}`), на мобильных — прокрутка
   от начала (`@media(max-width:640px){.tabs{justify-content:flex-start}}`).
5. `.tabs-row2` — «Пост 1» … «Пост N».
6. Заменить содержимое панелей `#podcast`, `#article`, `#post1`…`#postN`,
   `#transcript` на контент из шагов 1–4. Транскрибация: `.tr-toc` + список
   `.tr-section` с `id="t1"`, `"t2"`, … и `.tr-line` (`.tr-who.host` /
   `.tr-who.guest`).
7. Кнопки «Скачать .docx» у статьи и транскрибации (`.dl-btn` в
   `.doc-topbar`) — ссылки на `mba-mybrand/<slug>-podcastN-statya.docx` и
   `mba-mybrand/<slug>-podcastN-transkript.docx` (см. шаг 6 ниже).
8. FAQ вверху страницы (4 вопроса — видео/транскрибация/статья/посты) —
   переписать под конкретного героя только там, где упоминаются его
   реалии; сама структура ответов (конкретные площадки, шаги, что делать
   после публикации, как выгрузить свой стиль в ИИ) переносится как есть.
9. CSS-токены (`--red`, `--dark`, шрифты Unbounded/Geologica) — по умолчанию
   не трогать, это бренд Cantor. Менять только если у клиента есть свой
   фирменный стиль и это явно оговорено.

## 6. Docx-файлы

Сгенерировать через `docx` (npm, см. навык `docx`) два файла — статья и
транскрибация, тем же текстом, что и на странице (без личной подписи-плашки
у статьи, с реальными именами говорящих в транскрибации). Сохранить как
`mba-mybrand/<slug>-podcastN-statya.docx` и
`mba-mybrand/<slug>-podcastN-transkript.docx` — ссылки на них уже вшиты
в кнопки «Скачать .docx» (шаг 5.7).

## 7. Публикация и отметка в CRM

- Файл кладётся в `mba-mybrand/`, имя — `<slug>-podcastN`, **без расширения**.
- Коммит и пуш по обычному git-флоу репозитория (ветка `claude/...`, PR).
- После деплоя — отметить в CRM mba-mybrand, что тексты подкаста готовы:
  1. `GET https://mainweb.oxion-ezhkov.workers.dev/api/crm/clients` — найти
     клиента по имени (`clients[].name`), запомнить его `id`.
  2. В его `tasks.podcastN.texts` (тот же `N`, что в имени файла) выставить
     `{ "done": true, "comment": "https://cantor.agency/mba-mybrand/<slug>-podcastN" }`
     — CRM рисует `comment`-ссылку кликабельной иконкой рядом с чекбоксом.
  3. `PUT https://mainweb.oxion-ezhkov.workers.dev/api/crm/client` с телом
     `{ "id": "<client id>", "tasks": <полный объект tasks с обновлённым podcastN.texts> }`
     — **важно** отправлять весь `tasks`, а не только изменённое поле:
     эндпоинт заменяет `tasks` целиком (см. `sanitizeCrmTasks` в `_worker.js`).
     Не трогай остальные поля клиента и остальные подзадачи — только
     `podcastN.texts`.
  4. У API нет авторизации (кнопка входа в CRM — чисто клиентская), но это
     всё равно запись в реальную продовую базу — не экспериментируй на ней,
     обновляй только запись нужного клиента и только нужное поле.

## 8. Чек-лист перед сдачей

- [ ] Все факты/цифры в статье и постах подтверждаются транскрибацией —
      ничего не придумано и не искажено.
- [ ] В каждом посте кнопка «Копировать» реально копирует именно текст поста
      (совпадение `data-copy` ↔ `id`), без обрезков разметки, без красного
      цвета и без крупных заголовков внутри.
- [ ] В карточке «Подкаст» каждое поле копируется отдельно, кнопка
      «Скачать видео» ведёт на страницу Vimeo (не на embed-URL), таймкодов нет.
- [ ] Оглавление транскрибации (`.tr-toc`) кликабельно и попадает на нужные
      разделы (совпадение `href="#tN"` ↔ `id="tN"`).
- [ ] Число вкладок постов и их подписи соответствуют реальному числу постов.
- [ ] Обе кнопки «Скачать .docx» ведут на существующие файлы рядом со

      `https://cantor.agency/mba-mybrand/<slug>-podcastN` после деплоя,
      переключение табов и FAQ-аккордеон работают.
