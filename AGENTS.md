# Памятка Codex: Avito API проекта

Источник: прежние инструкции Claude в `CLAUDE.md`. Это рабочая шпаргалка, а не гарантия, что каждый маршрут не изменился. Перед использованием сверяйся с текущим `_worker.js`, особенно если получаешь ошибку или маршрут влияет на данные.

## Доступ и безопасность

- API сайта: `https://mainweb.oxion-ezhkov.workers.dev`.
- Для `/api/dashboard/*` нужен заголовок `x-dashboard-password: <пароль панели>`.
- Для `/api/avito/*` тот же заголовок передаёт секрет `AVITO_API_PASSWORD`; по заметкам Claude, если он не настроен, Worker использует пароль панели. Без подходящего секрета возможен `401`.
- Никогда не сохраняй пароль, токен или ключ в этом файле, репозитории, коммите или отчёте. Получай секрет только из разрешённого хранилища/окружения или попроси пользователя в текущей сессии.
- По умолчанию только чтение. Не отправляй сообщения, не одобряй черновики, не меняй настройки и не запускай синхронизацию/загрузку метрик без прямого запроса пользователя.
- Не считай маршрут безопасным только потому, что он использует GET. `/api/dashboard/avito-pull` — операция «Подтянуть»; старая инструкция указывает GET, но старый интерфейс вызывает её через POST. Сначала проверь текущую реализацию и её побочные эффекты. Без явного запроса не запускай.
- Для `/api/avito/raw` используй GET для чтения. POST допускается только к подтверждённым read-only методам Avito (статистика, расходы/история операций, цены VAS, баланс CPA, call tracking); проверь текущий allowlist в Worker. Любые остальные POST/PUT/DELETE запрещены без прямого запроса пользователя.

## С чего начинать

1. Получи `GET /api/dashboard/bootstrap`: проекты, привязки Avito (`avitoAccountId`), сохранённые дневные/месячные метрики и контекст панели.
2. Сопоставь проект и кабинет по `avitoAccountId`; при необходимости проверь `GET /api/avito/accounts` и `GET /api/dashboard/avito-links`.
3. Для показателей объявления/кабинета укажи период явно, запросив `GET /api/avito/overview?accountId=<id>&dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`.
4. Для диалогов получи список `GET /api/avito/chats?accountId=<id>&limit=100&offset=0`; при необходимости меняй offset. Затем загружай `GET /api/avito/messages?accountId=<id>&chatId=<id>` только для нужных диалогов.
5. Сверь прямые данные Avito с тем, что уже сохранено в панели. В ответе обозначь период, часовой пояс при необходимости и источник показателей.

## Основные маршруты

### Панель агентства

- `GET /api/dashboard/bootstrap` — проекты, дневные метрики (бюджет, просмотры, контакты, диагностика, продажи), месячная аналитика, задачи и сотрудники.
- `GET /api/dashboard/avito-yesterday?projectId=<id>&date=YYYY-MM-DD` — показатели одного кабинета за день и ошибки.
- `GET /api/dashboard/avito-links` — соответствие кабинетов клиентам.
- `GET /api/dashboard/reflection?week=YYYY-MM-DD` — недельная рефлексия; неделя начинается в среду.
- `GET /api/dashboard/mailings?month=YYYY-MM` — календарь рассылок: дата, клиент, бюджет, статус, контакты, результат и комментарий.
- `GET /api/dashboard/chat-log?projectId=<id>&from=YYYY-MM-DD&to=YYYY-MM-DD` — логи Telegram-чатов по проекту. Можно фильтровать по `chatId`/`threadId`; обычно доступно до 120 сообщений за последние 30 дней, порядок от старых к новым. Используй для поиска согласованных бюджетов, целей, рекомендаций и дат запусков.
- `GET /api/dashboard/avito-pull?date=YYYY-MM-DD` — упоминается в старой инструкции как подтягивание метрик. Потенциально записывает данные; не вызывать без явного запроса и проверки текущего кода.

### Кабинеты, статистика и переписки Avito

- `GET /api/avito/accounts` — доступные кабинеты (ID, имя, userId; секреты не должны возвращаться).
- `GET /api/avito/overview?accountId=<id>&dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD` — объявления и просмотры/контакты/избранное за период, рейтинг.
- `GET /api/avito/chats?accountId=<id>&limit=100&offset=0` — диалоги, новые сверху; можно постранично менять offset.
- `GET /api/avito/messages?accountId=<id>&chatId=<chat_id>` — сообщения диалога по времени от старых к новым; автор `manager` — кабинет клиента, `client` — покупатель/родитель/ученик.
- `GET /api/avito/autoload?accountId=<id>` — последний отчёт автозагрузки.
- `GET /api/avito/tariff?accountId=<id>` — подписка и история списаний (по старой инструкции — за 120 дней); без accountId может возвращать данные всех кабинетов. Сначала проверь текущий код и не выгружай лишнее.
- `GET /api/avito/raw?accountId=<id>&path=<путь Avito API>` — прокси к API Avito; в пути шаблон `{user_id}` заменяется ID кабинета. Используй только необходимый путь и минимальный период.

Сообщения о предложениях могут содержать неразрывные пробелы. Для поиска фраз «ознакомился с вашим предложением» или «заинтересовало ваше предложение» используй нормализацию пробелов/регулярное выражение `\s`. API, по старой заметке, не даёт общего количества отправленных предложений — не вычисляй его как достоверный факт без отдельного источника.

Запросы к Avito могут идти через прокси и занимать десятки секунд. Загружай переписки небольшими сериями, не запускай десятки параллельных запросов.

### ИИ-менеджер Avito

В старой инструкции указаны read-only маршруты; всё равно проверь текущие обработчики и не вызывай маршруты изменения состояния без разрешения:

- `GET /api/dashboard/ai-sales/state` — подключённые кабинеты и настройки; ключи моделей не должны возвращаться.
- `GET /api/dashboard/ai-sales/chats?accountId=<id>` — список диалогов и состояние обработки.
- `GET /api/dashboard/ai-sales/chat?accountId=<id>&chatId=<id>` — сообщения, черновик и предыдущие варианты.
- `GET /api/dashboard/ai-sales/feedback?accountId=<id>` — история правок/одобрений.
- `GET /api/dashboard/ai-sales/prompt?accountId=<id>` — промпт и связанные материалы базы знаний.

## Как отвечать по результатам

- Разделяй подтверждённые ответы API, сохранённые значения панели и собственные выводы.
- Указывай, какие кабинеты и даты проверены; не называй частичные данные полной аналитикой.
- При 401 сообщи, что требуется доступ, не подбирай и не обходи пароль.
- Если код и эта памятка расходятся, доверяй текущей реализации Worker и исправь эту памятку в следующем безопасном изменении.
